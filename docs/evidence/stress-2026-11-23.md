# 2026-11-23 · 压测可复跑：用仓库自带的量具重敲一遍，并给 2026-11-19 那篇补上可复现的入口

> **为什么有这一篇。** `docs/evidence/stress-2026-11-19.md` 是本仓库第一份压力测试证据，
> 数字是真的，但它当时用的 k6 脚本是**一次性量具**、躺在本机的临时目录里 ⇒
> **谁也复跑不了**（连下一个人找那个文件都找不到）。本篇用**仓库自带的**
> `scripts/stress_smoke.py`（纯 Python、零依赖、在库内）把同一类压力重新敲了一遍，
> 把「怎么敲」写成**可以照抄的命令**，并把产物作为**受版本控制的证据**入库。
>
> **目标依旧不碰 LLM 车道、不碰 court、不打第三方公网。** 本号全程未发一个模型请求
> （API 已关闭，且本轮也不需要）。

## 量具（仓库携带，可复跑）

| | |
|---|---|
| 工具 | `scripts/stress_smoke.py`（纯 Python · 只用标准库 · 无外部依赖） |
| 车道 A | **前门车道**：`apps/web/dist` 用回环 HTTP 服务托起，用真入口资源并发 GET |
| 车道 B | **定向车道**：`--target` + `--method/--header/--body` + `--expect-status`（撞库场景用 `401` 作期望） |
| 判定 | 每轮 `err_rate` 与 `p99` 进预算 ⇒ `OK` / `BUDGET-BLOWN`（退出码 0 / 1） |
| 诚实边界 | 量具自己写着：**这是本机此刻的读数，不是生产容量评级**；静态车道托的是 `dist/`，而生产是 uvicorn 里的 FastAPI |

## 车道 A · 前门（与周压测同参数 ⇒ 可比）

```
python scripts/stress_smoke.py --concurrency 48 --per-thread 2 --warmup 2 --rounds 2
```

产物：`docs/evidence/stress-2026-11-23-front-door.json`

| 轮 | total | ok | err | p50 | p95 | p99 | max |
|---|---|---|---|---|---|---|---|
| warmup 1/2 | 96 | 96 | — | — | — | 938.7ms | — |
| warmup 2/2 | 96 | 96 | — | — | — | 52.0ms | — |
| 1/2 | 96 | 96 | 0.00% | 72.4ms | 83.4ms | 85.1ms | 85.3ms |
| 2/2 | 96 | 96 | 0.00% | 83.6ms | 98.6ms | 103.9ms | 108.4ms |

⇒ verdict **OK**（worst err 0.00%、worst p99 103.9ms）。
⇒ 与 `docs/evidence/weekly-2026-11-18.json`（同参数，p99 1888.3ms）相比 **p99 降了约 18 倍**；
⇒ **但这不是「产品快了 18 倍」**：那一次是冷启动 + 这台机器上当时有别的车道在抢 CPU。
⇒ **同一档参数本号独立跑了两次**：p99 读到 **61.2ms** 与 **103.9ms** ⇒
⇒ **读数会抖**，本篇两个数都留着，不挑好看的那个报。

## 车道 A′ · 高并发（把量具推到 1024 请求/轮）

```
python scripts/stress_smoke.py --concurrency 128 --per-thread 8 --warmup 1 --rounds 3
```

产物：`docs/evidence/stress-2026-11-23-high-concurrency.json`

| 轮 | total | ok | err | p50 | p95 | p99 | max |
|---|---|---|---|---|---|---|---|
| warmup 1/1 | 1024 | **897** | — | — | — | 8136.6ms | — |
| 1/3 | 1024 | 1024 | 0.00% | 201.9ms | 234.3ms | 438.8ms | 467.6ms |
| 2/3 | 1024 | 1024 | 0.00% | 229.2ms | 259.7ms | 264.0ms | 269.8ms |
| 3/3 | 1024 | 1024 | 0.00% | 224.9ms | 247.3ms | 251.1ms | 254.6ms |

⇒ verdict **OK**（worst err 0.00%、worst p99 438.8ms）。

⇒ 它**不计入判定**（量具把 warmup 单列，正是这个道理）。
⇒ 这也说明：**没有 warmup 的压测数字没有意义** —— 它量的是冷启动，不是稳态。

## 车道 B · 撞库（**本轮未复跑**，如实记）

2026-11-19 那篇的撞库结论（8,276 次随机伪造 `X-API-Key` ⇒ 0 次成功、0 个 500、全部在
`hmac.compare_digest` 前被挡下）**数字保留**，但**本轮没能复跑**：

- 本机的 MySQL 容器**没有把 3306 发布到宿主机**（`docker ps` 里它没有端口映射），
  ⇒ 起 uvicorn 时连不上库 ⇒ 定向车道没有目标。
- 本号**没有**为了凑一条绿而伪造读数，**也没有**去改容器的端口映射
  （那是别人的运行环境，且改了会让读数变成另一台机器的读数）。

⇒ **可复跑入口已经就位**（量具在库内、命令在上面），等库能从宿主机访问时，
一条命令即可复跑：

```
python scripts/stress_smoke.py --target http://127.0.0.1:8027/jobs --method POST \
  --header "X-API-Key: forged-key-0000" --body '{"name":"stress"}' \
  --concurrency 32 --per-thread 4 --warmup 1 --rounds 2 --expect-status 401
```
