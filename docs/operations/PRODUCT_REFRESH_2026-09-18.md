- 修复零验收检查误报 VERIFIED；检查为空或有失败项时阻止通过，解释覆盖不足。
- GPT 结果不再套用 DeepSeek 示例价格；未配置价格时显示费用不可用。
- README 改为实际使用说明，历史基准移到单独文档，避免把历史结果当成商业 SLA。

## 真实验证

### 模型协议

通过用户指定的 `https://ynynzyy.xyz/v1`，使用 `gpt-6-astra`、`max`：
普通 Responses / Chat 请求均返回 HTTP 200；Responses 流式内容、JSON 输出、required 函数调用和工具结果续接成功。网页“测试连接”通过，记录耗时约 10.6 秒（单次观测，不是性能承诺）。

### AI 开发

任务 `80f80a2a-fd31-472f-ae5b-c35eb937d5d3` 使用独立测试仓库：

1. 模型生成 3 步中文计划。
2. 自动检查确认审批前 `calc.py` 没有变化。
3. 批准后真实模型把 `return x / 2` 改为 `return x * 2`。
4. 原测试没有修改，覆盖正数、负数和零；测试、类型检查通过。
5. 任务进入 `COMPLETED`。无构建配置，因此构建门标为 skipped，不作通过宣传。

首轮任务失败揭示了错误规划模板和错误 Python 环境，修复后上述第二轮完成。保留失败记录，未修改历史结果。

### 独立验收

对同一个 Python 仓库提交了真实 Verify 任务，证明 API → MySQL outbox → RabbitMQ → Worker → 模型 → 结果的链路可执行。实跑发现该需求未形成现有检查器可执行的契约；旧代码错误地判通过，已修正为覆盖不足阻止通过。Python 开发任务完成不能替代 Java/Spring 为主的 Verify 检查器覆盖。

复验任务 `d392d303-fc77-43ea-a57b-754d9d745b67` 实际返回 `BLOCKED`，附带零检查覆盖不足的原因；期间模型调用超过原租约限制，新增心跳续租正常工作。

### 页面与环境

桌面 1440px、手机 390px 进行了浏览器检查；手机页面没有横向溢出。模型配置、任务结果、导航和详情可访问。六个 Docker 基础服务健康。MinIO 使用官方 Quay 镜像，替代拉取失败的 Docker Hub 镜像。

## 当前边界

这是本地可用版本，不是商业化全部完成的承诺。团队身份、账单、签名证书已有模块，但实际收费、试点效果、客户 SLA、私有部署运维、广泛跨语言验收仍需对应配置与验证。实时事件仍有进程内存状态；MySQL 中的需求、计划、执行选择与结果持久化，计划审批可从已保存计划恢复，新的代码差异快照写入任务产物，在服务重启后仍可审阅。现有检查器没有覆盖的要求必须继续显示证据不足。

## 使用

启动：`pwsh scripts/start_local.ps1`。本机工作区登录密钥由脚本输出。
模型：侧栏“模型连接”；开发：侧栏“AI 开发”；已有改动：侧栏“变更验收”。
改服务端代码后：`pwsh scripts/start_local.ps1 -Restart`。
