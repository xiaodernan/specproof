# 2026 新版体验导览（WORLD TOUR） — SpecProof 的五道门

> 这份导览是给「没有 60 分钟、却想先看见铁证」的人写的。**五步各 3 分钟**，
> 每一步你输的都是真实数据；每一步不连网跑 CLI 也能先在屏幕前看一眼。
> 旧版镜头（`EXPERIENCE_GUIDE.md`）写于 60 分钟前；这是一版带史诗的短版。

## 第一门 · 案卷铁页 · `#/explorer` · the case file

打开侧栏 **案件档案 · The Case File**。你会看到：
- 卷首红印「验讫」（或受阻/待议）；
- 仓库 / 变更 / 开卷日期 / 案卷号四行原文；
- 验收条件 StatCard：2 条件 · 1 通过 · 1 未通过 · 0 未验证；
- 一条证据行：`AUTH-02 · runtime_diff（MAJOR） — 邮箱变更接口缺少认证注解`；
- 复现包 zip 名 + 报告路径（每次验收后即可下载）。
- **这是全系统仅有的一页**，把一切摊在红印之下——**没有 AI 给你的一致论调，只有服务器返回的数字**。

铁律：红字 = 验讫 / 受阻，不靠模型；缺字段永远写「未提供」。

## 第二门 · 铁证山 · `#/matrix` · the matrix

打开 **需求覆盖** 页。矩阵上每一行都是一条需求 → 一次裁决；每一格都是
`contract_id` 的眼神，不是文字游戏。挑一行 `review-court` 标铁（`base_pass_head_fail`）的，问自己：找到了吗？没找到也没关系——能被复现的 bug 才算铁，否则只算「可能对」。

铁律：矩阵不装饰，只承诺。

## 第三门 · 史官厅 · `#/epic` · the chronicles

打开 **史诗 · The Chronicles of SpecProof**。
- 六卷竹简式排版依次展开：卷〇 创世 — 卷五 史官纪要—直接结束；
- 每一卷都钉在本仓库真实提交号 + 账本号上——顺序不能错、不能删字；
- 页面上没有一个「建议」字段——全部都是「我曾把这件事钉在文件系统里」。

铁律：此卷历禁删、禁改字。宁可追加，不改已成之文。

## 第四门 · 巡览 · `#/tour` · the grand tour

**首次登陆后领你走六桩交互。**每一步都是真正点一下、按一下、盖一次印：
- 卷一 **连接工作区**（用你的访问令牌，不传给任何人）；
- 卷二 **读验收报告**（结论/条件/未验证——四张卡片逐字看）；
- 卷三 **站矩阵前问一句**"这是铁证还是纸"；
- 卷四 **读一条 finding**（severity / evidence_type / contracts）；
- 卷五 **打开 `#/epic` 读任意一卷**（查证 commit hash）；
- 卷六 **盖印**（复制史诗纪要，或盖上「验讫」章）。

完成 6/6 → 进度条满 → 「验讫」印盖出 → 页面上出现一句话：**"六卷齐盖；章落。"**
**全部在你自己的 localStorage 里发生——没服务器端的人为痕迹，没人会替你承认。**

铁律：每一桩动作必须你自己按钮按完，系统不代按。

## 第五门 · 缓存健康 · `#/usage` · the cash register

打开 **缓存健康** 页。
- 你看到的 `cached_tokens` 是实时打在 wkapi.pro 上的实测值；
- 命中率 75.2%–84%（A/B 实测见 `docs/operations/DEEP_OPTIMIZATION_PLAN.md` 的 #1679 / #1681）；
- 11 次真实调用机制图示、计入账本的公式、以及 "非流还存在吗" 的答复（不存在）— 都在这。

铁律：数字必须来自账本，不是仪表盘短语。

## 若你只能在屏幕前 3 分钟

1. `#/tour` → 点「连接工作区」→「盖上此卷」（一键盖第一卷）→ 观察红印落下 200ms 内无刷新。
2. `#/explorer` → 看见红印「验讫」四字，与你刚盖的那一枚相呼应。
3. `#/usage` → 找到今日命中率 >75%，旁白自问：我刚刚让多少个模型 call 免了写缓存？

铁证如山。挑一条你能敲下去的字面链路，你就是 SpecProof 的一颗齿。
