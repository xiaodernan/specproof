# 验收准确性实施与定向验证

日期：2026-09-18。对应深度优化计划 P1。这里的“准确性”指程序不会在缺失或矛盾证据时错误宣告通过，并不代表模型的通用正确率。

## 已实现

1. 新增 `evidence/verdict.py` 纯函数决策层。Worker、HTML 报告、CLI、自动验收摘要和合并证书复用同一组规则。判定复杂度随检查行数量线性增长，无数据库、网络或模型请求。
2. 每个 PASS 必须有契约标识、非占位的证据引用和实验记录；签发证书使用契约记录，至少要求每个契约独立有证据。一个无关联的全局摘要不能补齐某个契约的证据缺口。
3. 零检查、未知结果、缺失契约行、重复行、FAIL/PASS 冲突、汇总计数不一致、已确认问题和执行错误均无法判为 VERIFIED。覆盖按契约 ID 对照，防止用另一条无关检查替代漏检的需求。
4. Worker 持久化可读原因和有效覆盖计数；HTML 报告显示结论原因。矩阵生成时即将缺证据或实验的 PASS 降为 UNVERIFIED，前端与报告读到一致数据；历史的“PASS 但没证据”也不再视作有效通过。
5. 修复两个结果合并漏洞：既有 channel 内重复行不能把早期 FAIL 覆盖成 PASS；CLI 和自动验收签证书时不再以最后一条记录覆盖同契约的失败证据。
6. 静态检查仅读取每份源文件、schema 和测试快照一次，减少重复磁盘遍历；PASS 的证据改为绑定 Base/Head/需求快照的 `static:<contract>:<digest>`，明确属于静态证据。
7. 删除 Java 类时，遗留检查器可能跳过不存在的 Head 文件；现在该情况的静默 PASS 降为 UNVERIFIED，要求运行时验收。静态节点缺工作目录时保留已有节点的证据。

## 能力边界

证据引用存在不等于远端对象仍可下载；对象存在性、摘要复核由重放和证书消费环节负责。静态快照摘要证明输入身份，不能替代运行时行为证明。删除源码的保守降级可能增加人工审阅，但不会把未观测到的行为宣称为通过。没有以这些定向案例数字推断任意真实仓库、任意语言或模型的一般准确率。
