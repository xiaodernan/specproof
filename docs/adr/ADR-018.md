# ADR-018 — 为什么边缘网关是 Spring Cloud Gateway，而不是 NeMo/自研反向代理

状态: 已接受（2026-11-10；边缘模块落地于 #1544，至 #1582 逐渐收口）

背景: SpecProof 的 HTTP 入口需要一个「谁回答这个路径」的唯一事实源。当时的两个
平面（Spring Boot control-plane：租户/用户/webhook 处理/Outbox；Python FastAPI
agent runtime：产品 API）在功能上清晰分离，但谁来承担「所有路径都必须经过的入口」
这个问题一直没有答案。

决策: 用 **Spring Cloud Gateway**（Boot 3.4.3 + Spring Cloud 2024.0.1
(gateway-server 4.2.1)）作为产品的唯一反向代理 / 边缘网关。它暴露在
`services/gateway`，端口 `8080`（GATEWAY_PORT），管理端口 `8090`（loopback by
default, GATEWAY_MANAGEMENT_PORT/ADDRESS）。路由表在 `application.yml`，顺序即匹配顺序：
control-plane 有 6 条审核用路由（Method 限定 + `Path=` 精确匹配），**末位**是
`agent-runtime-default` 的 `Path=/**` 兜底——所有没被 control-plane 认领的路径都
落到 agent runtime。

```
routes 列表 (按匹配序):
  control-plane-jobs          GET  /api/v1/jobs,/api/v1/jobs/{id}
  control-plane-tenants       GET,POST /api/v1/tenants
  control-plane-tenant-item   GET  /api/v1/tenants/{id}
  control-plane-tenant-users  GET,POST /api/v1/tenants/{tenantId}/users
  control-plane-github-webhook POST /api/v1/webhooks/github
  agent-runtime-default       ANY  /**   → agent runtime (带 EdgeCircuitBreaker filter)
```

理由: 选择 SCG 而非自研 Nginx/HAProxy/自制层的核心论点：

1. **Java 栈知识集中**: 项目已有 control-plane（Java 21）和 Python agent runtime；
   加入一个 JVM 反向代理解决了"谁回答路径"的知识集中问题，不引入第三方配置语言。

2. **内建负载意识**: SCG 的断路器（Resilience4j）对 agent-runtime 上游失败做开闸，
   503+`request_id`（边缘自生成）+ 503 体 *也是普通 HTTP body*，agent runtime 立即
   获知「边缘维护路径」而不是猜。自研代理要得到同等语义得写 plugin。

3. **运维可见性**: SCG 以
   `management.endpoints.web.exposure.include` 自带 `/actuator/gateway/routes`
   （路由表 runtime 读数）、`/actuator/prometheus`（metrics 端点，含 histogram_quantile），
   无需 NATS 或额外 exporter 就能接入既有 SLO 看板/告警。自研代理解除不了这一点。

4. **与 Spring Boot 同源**，所以边缘的运维模型（management port、暴露白名单、
   同一套 Environment）和 control-plane 一致，学一个就会俩。

后果:

- SCG 不负责认证——两个上游各自认证（或继续不对外公开）；边缘原则上不做
  Security，不持有 token。
- 控制平面的路由**先匹配后特异**，`/**` catch-all **绝不能排在前面**；当前
  application.yml 顺序已被 `test_gateway_route_table_covers_every_plane_route.py`
  R3 钉死，改顺序会红。
- 上游拓扑不外泄：management 端口默认绑 loopback；compose observability 栈为 Prometheus
  抓取它（set `GATEWAY_MANAGEMENT_ADDRESS=0.0.0.0`，仅容器网内部可见），边缘对**公网**
  不答 `/actuator/gateway/routes`（已被 `GatewayActuatorRoutesTests.java`
  `theRouteTableIsNotServedOnTheEdgePort` 钉）。
- 端到端部署：边缘目前只组合进 `compose.observability.yml`（edge 服务在 observability
  profile），不进默认 `compose.production.yml`；生产启用边缘需 operator 显式决定。

对应 PRODUCTION_SPEC: §22 ADR-018（新附；不取代任何已有 ADR）；§2/§17（部署形态）。
