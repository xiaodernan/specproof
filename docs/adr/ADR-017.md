# ADR-017 — LLM 私有推理不保存

状态: 已接受 (2026-08)

背景: 验证管道把私有仓库内容与需求组装成 prompt 发给 LLM; 如果再把
prompt 与模型输出 (尤其是 reasoning_content 链式思维) 落盘归档,
就等于在系统里制造第二份"私有代码 + 推理过程"的敏感数据副本, 扩大
泄露面与合规负担。

决策: LLM 的私有推理不保存:
- prompt 全部临时构造 (compile_contracts / generate_counterexamples /
  review_court 等节点在内存中 format 后直接发送), 不写入任何存储;
- 响应的 reasoning_content 只进入内存中的 LLMResponse
  (providers/openai_compatible.py), 任何节点都不持久化它;
- 落盘/入库的只有结构化结论: jobs/contracts/findings/capsule 摘要与
  证据 digest (storage/mysql.py, storage/mongodb.py), finding 上只记
  court_source 之类的结构化标记, 不记模型原文;
- observability 只记录内核级 OTel span (节点名/状态/耗时), 不携带
  prompt 载荷;
- 敏感数据出站前统一走 providers/redaction.py 脱敏, 密钥类永不外发。

理由: 最小化敏感数据副本 — 私有代码只有"发往用户自选网关"这一条
出站路径, 系统内部不积累第二份; 需要排查时按证据链复现, 而不是
翻聊天记录, 与 ADR-015 的可重放原则一致。

后果: 无密钥落盘由 tests/security/test_no_key_leak.py (canary 自检)
与 test_no_secrets.py 持续把关; 调试成本上升 (没有"当时模型想了
什么"的存档), 这是隐私边界的既定代价。

对应 PRODUCTION_SPEC: §22 ADR-017; §0 安全前置。
