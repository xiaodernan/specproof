# ADR-003 — 为什么实现 Agent 与验证 Agent 隔离

状态: 已接受 (2026-08)

背景: 同一个模型既实现代码又验收代码, 相当于自己给自己签发合格证。
验收的基本前提是利益分离 (参考编译器的独立测试、金融的独立审计)。

决策: SpecProof 的验证管道只读三类输入 — 需求文本、用户批准的
Contract (agent/contracts/registry.py, 见 ADR-010)、Base/Head 两个
提交的内容与工具执行输出 (git diff、测试退出码、HTTP/DB 行为证据);
不读实现 Agent 的自我评价, 不接受 PR 描述中未经验证的声明。
Review Court (agent/nodes/review_court.py) 判定 BLOCKER 的六条件
全部来自真实执行记录, 而不是实现方的叙事; 生成的反例测试必须真实
编译并在 Base/Head 各自跑通才构成证据 (generate_counterexamples →
run_differential)。

理由: 让"实现"与"验收"的信息源完全分开, 一切结论来自实验而非自述,
这是产品"独立验收"定位的根基。

后果: 系统默认不信任实现方叙事; 证据链全程可追溯 (evidence_digest、
manifest_digest); 诚实代价是验证成本更高 — 每个案例都要真实执行,
不能只靠模型读代码下结论。

对应 PRODUCTION_SPEC: §22 ADR-003; §4 本质差异。
