# ADR-008 — 为什么做 Base/Head 差分

状态: 已接受 (2026-08)

背景: 只看 Head 无法归因 — 一个失败测试到底是本来就失败, 还是这个
PR 引入的? 验收评审要回答的正是"这个变更引入了什么"。

决策: 同一测试在 Base 与 Head 两个隔离 worktree 真跑, 比较 HTTP 响应、
数据库状态、异常与事件 (agent/nodes/run_differential.py)。判定四分类:
REGRESSION / COMPLIANT / AMBIGUOUS / UNEXPECTED_FIX, 其中 HTTP 行为
与 DB 状态取证结合 (如 DB_MUTATED_ON_UNAUTH) 时才可归因到具体
contract, 证据类型 base_pass_head_fail 携带双方 exit code。

理由: 差分把结论绑定到具体变更; "Base 通过、Head 失败" 是可重放的
事实, 不是模型判断; 这也为 BLOCKER 六条件 (见 ADR-004) 提供条件 2/3
的真实执行与归因证据。

后果: 每个案例必须携带 base_ref/head_ref (golden-cases 的
scenario.json); 双 worktree + 双执行使成本约翻倍, 但这是归因能力的
代价; 无归因的结论按 AMBIGUOUS 处理, 不强行下判定。

对应 PRODUCTION_SPEC: §22 ADR-008; §6 产品工作流。
