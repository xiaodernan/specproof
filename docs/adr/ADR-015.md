# ADR-015 — Bug Capsule 可重放格式

状态: 已接受 (2026-08)

背景: 一个 Finding 若无法复现, 就只是一句评论。胶囊必须是"打开就能
重放"的自包含包, 而不是一堆引用了宿主机状态的散文件。

决策: Bug Capsule 固定目录结构 (agent/nodes/create_capsule.py,
仓库内 capsules/capsule-<FINDING_ID>/ 为真实样例):
- manifest.json — finding_id/severity/confidence/evidence_digest/
  manifest_digest (SHA-256; 命名遵循 digest 不是签名原则)/blocker_check;
- requirement.json / contract.json / finding.json — 需求、契约与
  Finding 原文 (含 evidence_type 与六条件结果);
- fixtures/base-ref.txt + head-ref.txt — 复现所需的两个提交引用;
- generated-tests/SpecProofGeneratedTest.java — 反例测试源码;
- environment/.env.template — 只含 replace_me 占位符;
- run.sh / run.ps1 — 实际可执行的回放命令 (git checkout 对应 ref +
  mvnw test + 结果对比, Windows/Linux 双脚本);
- README.md — 复现说明。
节点同时产出目录与 .zip 包; specproof replay 解包并定位 run.sh 执行。

理由: 自包含 + 双平台脚本 + 真实提交引用, 让"可重放"成为可验证的
事实; 摘要链 (evidence_digest/manifest_digest) 让胶囊内容可校验。

后果与局限: 胶囊只在 BLOCKER/MAJOR 的 confirmed finding 上生成;
自动化 replay 成功率测量 (Go/No-Go #4) 尚未全量跑 — 现有集成测试
tests/integration/test_phase_acceptance.py 在无 zip 时显式 skip,
不伪造通过。

对应 PRODUCTION_SPEC: §22 ADR-015; §14 SLO Capsule Replay 成功率。
