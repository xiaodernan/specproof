# ADR-005 — 为什么同时使用 MySQL 与 MongoDB

状态: 已接受 (2026-08)

背景: 业务状态需要 ACID 事务、状态机与唯一约束; 实验工件 (checkpoint、
差分执行记录、证据包) schema 不稳定、体积大、需要嵌套结构。单一
数据库无法同时做好两者。

决策: MySQL 存业务事实 — verification_jobs/contracts/findings/outbox
(storage/mysql.py), 强事务 + 状态机 (InvalidStateTransition) + 唯一约束,
消息投递走 Transactional Outbox; MongoDB 存结构复杂、频繁演进的
实验工件 — agent_checkpoints/differential_runs/evidence_packs
(storage/mongodb.py), 并承担工件链校验 (verify_artifact_chain 对
MinIO 对象做存在性核查)。

理由: 让"事实"与"工件"分离 — MySQL 是唯一事实源, 工件按 job_id 可
重建; 审计视图可以从工件链重建证据, 而 MongoDB 损坏不影响业务结论。

后果: 业务查询永不依赖 MongoDB; evidence_packs 以 (job_id, contract_id)
唯一 upsert; 运营上多了一个数据库, 但换来事实层的强一致与工件层的
灵活性。

对应 PRODUCTION_SPEC: §22 ADR-005; §8 所有技术的真实职责。
