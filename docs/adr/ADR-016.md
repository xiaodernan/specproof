# ADR-016 — 为什么 v1.0 不使用 Kubernetes

状态: 已接受 (2026-07)

背景: 目标市场是 1~20 人团队的单机/私有部署 (PRODUCTION_SPEC §2、
§17 单机生产部署), Kubernetes 多集群运维被明确列入"不在 v1.0 承诺"
的清单; 对这批用户, k8s 是运维负担而不是价值。

决策: v1.0 部署形态 = 单机 Docker Compose: 仓库根的
compose.phase0.yml (Phase 0 基础设施: MySQL/MongoDB/ES/Redis/
RabbitMQ/MinIO) 与 compose.production.yml (生产拓扑), 服务间靠
Compose 网络互通; 仓库中没有任何 k8s/helm 清单, 也没有引入编排
抽象层。

理由: Compose 一条命令起全部依赖, 与"单兵演示效果"评分目标一致;
把 k8s 相关的复杂度 (调度、服务网格、多集群) 推迟到真的需要多机/
多租户规模之后, 避免过早投资。

后果: v1.0 的水平扩展上限受单机约束 (这是产品边界, 不是缺陷);
当试点规模突破单机后, 再评估容器编排 (ADR 可被后续决策取代);
基础设施文件集中在 compose.*.yml + docker/, 保持部署路径单一。

对应 PRODUCTION_SPEC: §22 ADR-016; §2/§17。
