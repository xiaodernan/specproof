# ADR-010 — 为什么 Contract 必须人工批准

状态: 已接受 (2026-08)

背景: 需求永远有歧义; 把需求编译成可执行契约是"解释性"动作, 解释
错了验收就全错。让模型自己解释又自己执行, 等于自己给自己出考卷。

决策: 从 Issue/ADR/文档提取的候选 Contract 必须经用户批准后才进入
验证计划 (agent/contracts/registry.py: propose → approve/reject,
approve 要求 --by 记录审批人, 已批准的契约不会因重复 propose 被静默
撤销; cli/specproof/commands/contract.py 提供 propose/approve/reject/
list)。verify 命令用 --use-approved-contracts 时只加载 registry 中
按 (repo, spec digest) 批准的契约; 未批准的候选不参与 BLOCKER 判定
(review_court 六条件之 1_approved_contract)。

理由: 人工批准把"需求解释错了谁负责"的产品责任边界划清楚; 审批人
与原因的审计链 (approved_by/reason) 使验收可追责。

后果与局限: Contract 有版本与审批记录, 未批准的契约只做建议不参与
判定; Phase 0 的兼容默认是隐式批准 (require_approved_contracts=False
时候选默认 approved=True, compile_contracts 的注释写明这是向后兼容
路径), 生产验收应显式开启 --use-approved-contracts。

对应 PRODUCTION_SPEC: §22 ADR-010; §6 产品工作流。
