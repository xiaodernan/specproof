# ADR-002 — 为什么先只支持 Spring Backend

状态: 已接受 (2026-08)

背景: 差分执行、契约检查器、变异测试都需要深度的框架语义 — 如何编译、
如何运行单测、注解在什么位置生效、事件怎么发布。一次性支持所有语言
会稀释每个检查器的质量。

决策: v1.0 只支持 Java 21 + Spring Boot 3.x + Maven/Gradle + JUnit 5 +
MySQL/Redis/RabbitMQ + OpenAPI 3.x (PRODUCTION_SPEC §2 首个生产支持范围)。
仓库内的检查器只面向该栈实现: agent/checkers/java_source.py 提供
Java 源码契约检查与注解切分, agent/checkers/constitution.py 提供需求
宪章检查, experiments/mutation.py 的算子只针对 Java/Spring 结构
(@PreAuthorize/@Transactional、null 检查、事件发布等), 差分执行通过
Maven Wrapper (demo/spring-backend/mvnw) 自包含构建。

理由: 先在一个栈上把"证据密度"做满 — 每一个 Finding 都有可执行、
可重放、可归因的证据 — 再横向复制; 同时与目标市场 (1~20 人、
Spring Boot 后端、MySQL/Redis/RabbitMQ 的团队) 精确对齐。

后果: 检查器注册表按框架组织 (agent/checkers/); 第二阶段才支持
FastAPI、Node.js/NestJS、PostgreSQL、Kafka (PRODUCTION_SPEC §2)。
Java 之外的仓库只能得到有限验证, 这是明确的范围裁剪而非缺陷。

对应 PRODUCTION_SPEC: §22 ADR-002; §2 明确目标市场。
