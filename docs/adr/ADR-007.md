# ADR-007 — 为什么使用 Elasticsearch Hybrid Search

状态: 已接受 (2026-08; BM25 + 确定性符号图已实现, 向量通道预留)

背景: 契约编译 (compile_contracts) 需要从仓库里找出与需求相关的代码
上下文。纯关键词检索找不准语义邻居 (一个方法与其调用者/被调用者),
依赖外部 embedding 服务又会把私有仓库内容送到第三方, 与"私有部署/
自带 Key"的产品定位冲突 (PRODUCTION_SPEC §2)。

决策: 使用 Elasticsearch 做混合检索 (PRODUCTION_SPEC §22 ADR-007),
当前实现分两层:
1. BM25 关键词层 — storage/elasticsearch.py: 仓库快照按方法级块索引
   (AST-free 符号切分, 复用 agent/checkers/java_source.py 的
   _split_with_annotations), 查询在 content 与 symbol 两个字段上做
   match, 并强制 repo term 过滤实现仓库隔离 (delete_repo + 重索引
   保证幂等)。
2. 确定性符号图层 — agent/repo_graph.py: 构建类/方法/调用点符号图,
   用 expand_hits 把 BM25 命中扩展为其语义邻域 (被调用者/调用者/
   同类的兄弟方法), 不依赖任何外部 embedding 服务。
   agent/nodes/retrieve_repository_context.py 把两层串成管道:
   index → search_code → graph.expand_hits → 合并上下文。

理由: 关键词保证可解释、可复现; 符号图扩展补上"语义邻域"而无需外部
模型; 两者都是确定性的, 验证上下文可以逐位复现。

后果与局限: index 的 mapping 已声明 dense_vector (dims=1536,
index=false) 作为向量通道预留, 但当前没有任何代码写入 embedding,
也没有 knn 查询 — 真正的向量检索尚未实现; ES 不可用时检索节点
返回 "retrieval_note: Elasticsearch unavailable" 并跳过 (降级而非
崩溃), 契约编译退回仅依赖需求文本的路径。

对应 PRODUCTION_SPEC: §22 ADR-007; §8 Elasticsearch 职责。
