# ADR-019 — 为什么边缘用 Resilience4j RateLimiter，而不是 SCG RequestRateLimiter / WAF / 网关限流

状态: 已接受（2026-11-11；实现于 #1589，随边缘一起落地）

背景: 边缘落地时（ADR-018，#1544-#1586）有了路由表顺序即匹配序、
Resilience4j 断路器（保护上游）、池/路由指标、`/actuator/prometheus`；
但**入向**没有任何流控：公开产品的 API 面（agent runtime，catch-all）可以
被单个调用方无界打爆，进而挤掉其他租户的可用性——断路器只防上游死，
不防调用方狂奔。

决策: 在 `services/gateway` 的 catch-all 路由（`agent-runtime-default`）挂一个
**EdgeRateLimiter** 过滤器（`EdgeRateLimiterGatewayFilterFactory`，名称取自
`name() = "EdgeRateLimiter"`）：

- 引擎 = **Resilience4j RateLimiter**（`resilience4j-ratelimiter` 2.2.0，与
  breaker 同版、同一 `RateLimiterRegistry` 家族、同一 Prometheus 采集腿）；
  不接 Spring Cloud Gateway 的 `RequestRateLimiter`（它是 Redis-based，把
  Redis 拖进 edge 的数据面——edge 需要无状态、可随 compose 观测网启动）；
- 令牌桶 **50 permits / 1s**，`timeoutDuration = PT0S`——空桶**立即本地应答 429**，
  绝不排队（排队 = edge 手握连接逼近自己保护的上游的样子）；
- 429 体沿用边缘错误约定：`{"error":"rate_limited","edge":"rate-limit",
  "retry_after_seconds":1,"request_id":"..."}`，状态码 429，附 `Retry-After: 1`
  头；`request_id` 由 ADR-018 的 `EdgeRequestIdGlobalFilter` 先生成并传播；
- **全局单桶，不分钥**：edge 不做认证（ADR-018），无 principal/tenant 可分，
  分钥就是伪造认证；每调用方限流应在 agent runtime 自己的限流器做
  （它持有身份），那是后续投放的任务；
- control-plane 路由**不挂**限流器——它们是带 Method 的内部外观，量级小且
  调用方明确；要限就在公共 API 面限，暴露面清楚。

理由:

1. **与断路器同源**——同一个 resilience4j 行，同一套 Prometheus 抓法
   （`resilience4j_ratelimiter_available_permissions{name=...}` gauge、
   `resilience4j_ratelimiter_waiting_threads`），加一个自建计数器
   `specproof.gateway.rate.limited`（Prometheus 出场名
   `specproof_gateway_rate_limited_total{limiter="specproof-edge-public"}`），
   操作员可以一眼区分"正在 shed load"与"上游饱和"。

2. **边缘不新增有状态依赖**——令牌桶在内存，重启归零，无共享状态；单机
   compose 部署下这是正确量级；多节点时一致性交给上游自身限流（见后果）。

3. **429 语义清楚**——调用方被告知降频（Retry-After），而不是上游坏
   （503）；两种信号在看板上永远可分。

后果:

- 限额是**静态 50/s**、不按调用方、不按路由可调——全部写在 `application.yml`
  的 filter args 里（`limitForPeriod/limitRefreshPeriod/timeoutDuration`），
  改数 = 改文件 + 重启，不引入运行时改参端点；
- 单实例内存桶：如果某天 edge 水平扩容成 N 副本，桶容量也随之 ×N——该
  场景的分钥 + 一致性限流属于"引入 Redis 之后"的后话，会另写 ADR 取代本条；
- 限流**只对外**，不对内部健康/metrics 端口生效（管理面在独立 loopback
  端口，不经过 catch-all）；
- 看板尚无限流器专属面板（series 已在 `/actuator/prometheus` 里，panel 59
  留给下次仪表盘迭代，避免同时动 dashboard 声明门）。
