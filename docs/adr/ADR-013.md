# ADR-013 — Sandbox 威胁模型

状态: 已接受 (2026-08)

背景: 验证管道要在 PR 的代码上执行 Maven 构建与测试, 而 PR 内容
(pom.xml、测试代码、构建插件) 是**不可信输入** — 直接在宿主机上跑
Maven 等于让恶意 PR 以宿主机权限执行任意代码并读取宿主机密钥
(LLM_API_KEY 等)。

决策: 实验命令一律经 sandbox/runner.py 在 Docker 容器内执行
(默认镜像 maven:3.9-eclipse-temurin-21):
- --network none (无外联, 不泄露数据);
- --cap-drop ALL + --security-opt no-new-privileges (无提权);
- --memory/--cpus 资源上限 (SPECPROOF_SANDBOX_MEMORY/CPUS);
- 挂载的是 throwaway worktree 拷贝而非仓库本体, /work 为工作目录;
- --tmpfs /tmp (noexec,nosuid, 运行间不持久);
- 可写 ~/.m2 依赖缓存卷 (离线构建 -o 的前提);
- 不挂 docker.sock、不传递宿主环境变量。

降级策略是显式且诚实的 (SandboxResult.mode): mode=auto 时 Docker
可用则用, 不可用则本地执行并记录 local_fallback; mode=docker 强制,
不可用即硬错误; mode=local 仅限显式开发模式, 绝不用于生产。
镜像拉取进程级缓存一次失败, 避免每次调用都挂 900s。

理由: 把"执行不可信代码"从"信任问题"变成"边界问题"; 每次降级都被
记录在结果里, 审计者知道这次执行到底有没有隔离。

后果: 生产环境必须保证 Docker 可用 (compose 部署); 无网络使所有依赖
必须来自预置缓存卷; 本地开发模式 (SPECPROOF_SANDBOX=local) 带明显
的标记, 不能混入生产证据链。

对应 PRODUCTION_SPEC: §22 ADR-013; §12 Sandbox 威胁模型。
