# 销售手册 (SALES PITCH) — 怎么把这个产品卖出去

## 1. 定位一句话 (电梯陈述, 30 秒)
"现在 1-20 人的团队都用 AI 写代码了, 但没人敢对 AI 写的 PR 负责 —
SpecProof 是 AI 代码的独立验收方: 需求→契约→差分实验→可重放证据→签名证书,
合并前把回归拦下来, 通过后给你一份机器可验证的合格证。"

## 2. 目标客户画像 (先卖给谁)
- 1-20 人团队, 重度使用 Claude Code/Cursor/Codex/DeepSeek 写后端 (Spring Boot);
- 缺资深 Review 人力, 怕 AI 代码上线出事;
- 要私有部署/自带模型 Key, 不想把私有仓库交给第三方 SaaS;
- 已经吃过"AI 改崩了生产"的亏, 或即将上 AI 提效。

## 3. 产品化形态与定价 (PRODUCTION_SPEC §16)
- Community (免费): CLI + 本地验证 + 单仓库 + BYOK + HTML 报告 + 基础胶囊。
- Team Self-Hosted (主卖): GitHub App + 多仓库 + 契约中心 + Dashboard + 审计 + 证书 + 评测 — 按团队年费。
- Hosted BYOK (进阶): 托管控制面 + 自带 Key + 临时沙箱 + 按 Verification Job 计费。
卖点不是"更多 AI 评论", 而是"AI 生成变更的独立验收证据" — 按 Job 收费天然成立。

## 4. 三大差异化 (对手打不了的三张牌)
1. 契约编译器: 需求→可执行契约 (11+ 族), 人工审批, 版本化 — 对手只会"模型提意见"。
2. 证据链: Base/Head 全栈差分 + 变异测试 + 可重放胶囊 + Ed25519 证书 + 契约血缘
   (篡改可证伪) — 对手给结论, 我们给可验证的因果链。
3. 中立性: 给任何 Agent (Claude Code/Codex/Cursor/自研) 的产物验收并签发 — 球员裁判分离。

## 5. 引用数字 (全部真实实测, 面试/销售通用)
- 100 金案例: Recall/Precision/F1 = 100/100/100, 0 误报;
- 裸 DeepSeek V4 Pro 看 Diff 基线: 发现率 100% 但严格归因 0%、5 误报、1 次被注入影响;
  SpecProof: 100/100/100、0 误报、0 注入影响 → +100pp (Go/No-Go #14);
- SpecCraft (开发 Agent): 10 任务微基准完成率 90%、平均迭代 1.1、陷阱拦截率 100%;
- 真实网关: 11 维探测 8/11 → 按能力降级 (strict_tool_calls 400 → JSON Envelope);
- 测试: 867 个机器可判用例; 门禁 ruff/mypy/bandit/pytest 全绿。

## 6. 常见反对意见与回应
- "已经有 CodeRabbit/Qodo 了" → 它们给评论, 我们给契约级证据 + 签名证书 +
  可重放胶囊; 评论可以争论, 证据只能复现。
- "模型直接看 Diff 不就行了?" → 实测: 裸模型归因 0%、5 误报、被注入影响;
  我们把"看"变成"编译成契约再验证"。
- "贵/复杂" → Community 免费, 一条命令出报告; Team 版价格按被拦下的生产事故成本定价。
- "私有代码安全吗" → 全部私有部署 + BYOK; 推理内容不落盘 (ADR-017); 0 密钥泄漏门禁。

## 7. 演示剧本 (5 分钟, 用 EXPERIENCE_GUIDE 第 2/4 步)
1) 现场 verify 一条 PR → BLOCKER + 胶囊重放 (30s 建立可信);
2) 现场让 SpecCraft+V4 Pro 修一个 bug → 1 次迭代收敛 (展示"开发+验收"闭环);
3) 打开 Dashboard → 真实数据聚合 (展示企业版完整度);
4) 丢出 100 案例与基线对比数字 (展示评测深度);
5) 收尾一句: "写代码的不能给自己签字 — 我们把签字权做成了可验证的产品。"

## 8. 边界诚实 (销售时同样要说)
v1.0 只做 Spring Boot 后端 + MySQL/Redis/RabbitMQ + GitHub; 不自动合并主分支;
不做形式化证明; 单机部署, 无 K8s。诚实边界比过度承诺更利于成交。
