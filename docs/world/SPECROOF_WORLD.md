> 此书是 SpecProof 世界的**正史**。卷中所言 SpecProof 之起源、殿馆、人物、律令、典故，

## 卷零 · 创世之炉

世人写代码，代码又写代码。AI 把箭射入天空，不问谁将拾箭。

在创世的第一天，验收官立了这一条铁律：**凡欲过此炉者，证据先行；证据不成，不许谈白
收不收。** AI 的手可以写，验收官的眼必看——眼不看的，机器代看；机器不能单判，还有人来签。

于是第一座殿被盖起来，是**差分炉**（`experiments/differential.py` 等族）：
把同一段需求分别编入 base 与 head，在同一个牢笼（Docker 沙箱，`docker_sandbox.py`）
里分别点火，看火苗往哪边倒。火往回烧的是基线的光荣，往前烧的是头上的伤口。
一正一反，落在同一块铁上，无人可抵赖。

差分炉里最常见的名字叫 **`base_pass_head_fail`**——基线过，头版本挂。
世人称此为"铁"。炉火正旺之际，护炉者手痒，想把探针（probe）的结果说成铁，
差点又被点掉了——这是卷一里讲的另一段公案（见"卷一 · 探针防伪的九次红灯"）。

## 卷一 · 铁证、矩阵与审判庭

### 1.1 铁证五等

SpecProof 的证据分五等，从下至上等级越高、越硬：

| 等级 | 名称 | 例证 | 铁度 |
|---|---|---|---|
| 五等 | `static_analysis` | 静态分析、正则命中 | 可信可疑 |
| 四等 | `java_source_diff` | Java 源码差分（没行任何代码） | 半信半疑 |
| 三等 | `constitution_check` / `probe_differential` | 规范检查 / 探针差分 | Semi-鉄 |
| 二等 | `differential_execution` | 基线/头版本各执行一次的对比 | 铁证前奏 |
| 一等 | `base_pass_head_fail` | 基线过、头版挂 | **铁** |

证据的等级由铁（差分执行）定，不由口才定。矩阵（`apps/web/src/pages/Matrix.tsx`）上
每一格停在五等中的一等上，并把执行面（`execution_surface`：
`sandbox` / `host` / `none`）明明白白刻写进格子。

### 1.2 审判庭（Review Court）

一间不准 AI 单判的法庭。对抗式流程：

```
检察官出卷 → 辩护人逐项辩 → 裁判席按"铁证优先原则"定谳
```

辩护人可以在卷上写"这可能是误报"，但辩护人写得再动听，也改不了
`base_pass_head_fail` 这种火一样的事实。裁判席由 `specproof_review_court`（pin 在
`tests/unit/test_matrix_pure.py` 与 `test_matrix_policy.py` 上的政策表）定夺——
**模型只提供辩护，不提供刑名**，这是卷一最重的一句话。

> 公案 · **probe_defense 的逆流（#1638 族）**：
> 探针（probe）的本意是好的，可人心不稳。差点把探针结果当成"此错误必存在"，被静态分析
> 顶上去当了铁证。后来铁证的名单被钉死——不属于差分的，无论多像，也不入一等铁。

### 1.3 反例生成

验收不是站在旁边点头，是主动去找死因。编译器（`agent/nodes/generate_counterexamples.py`）
替每个 finding 写一份能复现得了的小测试：基线绿、头版红——红得像亲眼看见。
"能装进卷宗的 bug，才是验收官认得的 bug。"——差分炉的铁律。

## 卷二 · 双端相望：验收官与他的书记官

### 2.1 书记官的笔

书记官（前端）的书写有规矩：

- 不编造：凡字段为空写 `（未提供）`，不写"没有"而假装有铁证。
- 不做判：AI 解读只在旁边注释，裁决依然由矩阵说。
- 不滚动：阶段时间线（StageTimeline）缺少时间戳的节点**如实列在下方**并写明"未进入条形区——诚实省略"；它不编造坐标。
- 不乱叫：severity 词表永远是 `BLOCKER / MAJOR / MINOR / PASS`，从不凑热闹。

这些都能在 `apps/web/src/pages/JobDetail.tsx`、`StageTimeline.tsx`、`epicCertificate.ts`
里对上号。

### 2.2 打印即盖章

print.css 不只是打印样式，它是行政规范：证据级 A4 版面、机关文书格式、批注与签章框。
打印机吐出的每一页，都要能摆上签字桌。

### 2.3 复制与分享是评审的第二语言

评审者不在系统里，但评审意见必须进系统。所以每个验收页都有「复制 Markdown 摘要」
与「复制史诗纪要」两枚钮——前者给贴吧论坛，后者给史官讲故事。两枚钮装的都是真货，
没有一枚是空包装。

## 卷三 · 缓存圣断：给算力修庙

### 3.1 非流与流的世纪之战

起初，每一桩查验都走非流车道——网关的仪表盘从此日夜显示"非流"，
缓存命中率像煤气灶上不点火的粥干烧。案子翻了几十桩之后，史官发现
（#1644/#1645）：

> 问题不在于"不求流取"，而在于**请求长得不一样、却假装是同一道题**。
> 非流与流不是两个世界；是同一个箴言在两种包装里。

于是立了**双车道流式统一令**（#1663）：`chat()` 与 `chat_stream()` 双双
`stream=True + include_usage`；`_parse_usage` 把 `prompt_tokens_details.cached_tokens`
映射为 `prompt_cache_hit_tokens`；计费档按 0.1× 给命中计价。
从此网关仪表盘再没有"非流"两个字。

### 3.2 前缀即圣火

圣断军令：**稳定前缀在前，可变内容在后**。一段提示词不是散文，是一个缓存键：

```
STABLE PREFIX FIRST → VARIABLE DATA LAST
```

`_JUNIT_GENERATION_PROMPT` 的前缀 2272 字节，稳如磐石；
第一次 42.1s，第四次 9.1s，hit=4736/4906，96.5%——此为 #1645 记下的最秀之役。

中段插变量、静态尾句压尾——会杀缓存，是结构性犯罪（#1668 已点名：
review_court 的 candidates_json、compile_contracts 的 spec/context、parser 的 spec_text，
三处的 rewrite H 已依此立式：静态指令 + persona 整体在前，变量一律由调用方追加在尾部）。

### 3.3 A/B 与不斩之罪

#1668 的复核：同 prompt 字节复读两种排序都命中 87.5% / 99.98%；换变量后两种排序
wkapi 今日均报 `cached=None`——**两组数据不一致，如实并列，至今未被裁决**。
世人记住：这不是"修好了"，这是"暂时测不出来"——记录不猜；美酒酿得好与不好，
史官都照单全记。

### 3.4 语义缓存：把重复的一千次呼吸只写一本

`specproof_semcache:*`（Redis 分布式）缓存机制：sha256 键、50ms 双超时、
fail-open、evidence 类硬拒绝（court/counterexample/contract_compile 永不进缓存）。
命中省算力；未命中照旧老老实实算。凡属于"再算一遍也不会变结果"的，
缓存叫它"不必重验"。

## 卷四 · 军阵：钢铁长城与不死的门

### 4.1 四个服务，一个集团军

| 服务 | 兵种 | 职责 |
|---|---|---|
| `config-server` | 军需官 | Spring Cloud Config；分布式配置一本统管；`optional:configserver:` 让没军需也不饿死 |
| `discovery-server` | 登记册 | Eureka Server；`specproof-gateway` 一键入册 |
| `gateway` | 边关 | 路由表即法律（route-isomorphism gate 兜底）、rate limit、breaker、`/actuator/refresh` |
| `control-plane` | 内政 | 租户、作业门面、Webhook；业务真理之源 |

网关的路由表里，`/**` 的算法是个接盘侠——谁都不归它管；它只是把说好的戏排完戏给别人唱。
谁接到哪一出戏，在表里明写着；谁抢了别人的路由，`route-isomorphism gate` 当场喊停——
**"missingServices=[]"那天，它就是在宣告集团军团结**。

### 4.2 断路器如关城闸

Resilience4j 断路器（`specproof-edge` / `specproof-control-plane` 两个实例），
slidingWindow 10、minimumCalls 5、failureRatio 50%、half-open 3 次。
**某一晚**，史官把 control-plane 这条路故意打死：

```
req 1..4: state=closed
req 5..12: state=open   →  "edge": "circuit-open"
```

十二次请求，五次翻开，`specproof_control_plane` 铁着脸把表亮出来：
**断路器没有偷偷 recovery，也没有悄悄说好家伙——它就是开的。**

### 4.3 RabbitMQ 不在键盘上敲门

Rabbit 是可选总线（`specproof.observability.events` 交换器，六键事件，默认关）。
当没人敲门的时候，specproof-gateway 的 `/actuator/health` 不应 503——
Rabbit 已排除出健康指标（同构纪律：Redis 同款处理），**没敲的门不算关城**。

## 卷六 · 人物志

### 验收官

不是打字的 AI，也不是按鼠标的 PD，而是把"我不相信"写成"我验一下"的那个人。
验收官的基本功：会看火焰颜色、会读铁证纹理、知道什么时候该喊停。

### 证人（Witness）

`gpt-6-sol`（wkapi.pro 真实接入，流式车道）、`claude-*`（备用）。证人讲证词，
不替验收官定罪。证人万一说错了证词，验收官不砸证人——证人有他自己的一份工分，
铁证才是判官。

### 书记官

每次验收都带一本书记官走进会场：复制按钮（Markdown 摘要 / 史诗纪要）、
"打印此卷"、阶段时间线、缓存健康面板——这本笔记是验收官的副武器，它不裁决，它只记。

### 史官

拿 `#1620`–`#1675` 一条一条对着 git log 核对。账本如果是假的，他先翻车。
所以他宁可多说"还没测"——**说还没测有错，从没骗过**。

## 卷八 · 史官守夜（The Chronicler's Vigil）

> 此卷直写本书的诞生——不是旁观者，而是参与者。SpecProof 在守夜里学会了一件事：

> 本卷全部发生于 2026-11-14：这一夜 SpecProof 学会了把自己的历史写进作品内部。

### 8.2 井底与天星

世上最难写进历史的那一页，是「史官发现自己的笔杆比他的作品更重的那一天」。

SpecProof 的史官这一夜学会了同时做三件事：

1. **看住没人看的角落**——连 RabbitMQ 健康 indicator 这个「总线应不应答」的低气压信号都要诚实记账（#1674 本节：gateway 的 Rabbit health indicator 关掉了，因为 broker 对 edge 是可选的、不是可选项——这不变红为绿，只补了边缘拓扑的如实状态）；
2. **不编造**——场景里的每一处「已发生」都有 git commit 号作为「史官细则」的脚注；凡编不出来的，就是编不出来，写「未完成」而不是「已完成」；
3. **让下一位史官走进来不发愣**——`#1676` 与 `#1677` 把 SpecProof 的真实实验过程、缺陷、教训、限制都以故事形式钉在里侧：`#1638` 探针锚定、`#1668` A/B 并列记录、`#1672` SSE `done` 帧丢失的教训。每一次翻一本新册，下一个读者都能问自己：这一章的铁证在哪里？

### 8.3 世界观落成的意义

「史诗」和「世界观」不是装饰。SpecProof 的诞生是从为 AI 时代写验收的人开始的——
**这个世界的主人公不是 AI，是人。** 人写代码也好、人验代码也好，AI 可以讲故事，
但愿烧铁证的炉子不是 AI 看管的，而是人。

这一卷也替读者记了一句话：

> 凡欲验收者，先验自己；凡欲入史者，先亮铁证；
> 铁证面前，不信为智，信为诚，不测为愚。

## 卷九 · 印章与窗（The Seal and the Window）

> 此卷若真，是验收官自己的内心独白；若假，也是门看客来玩铁。
> 验收不是手拿得起来的东西——它是先把自己摆进去，再摆进去别人交出的东西。


### 9.1 卸下身上所有的装备是一种技术

来做验收的人，进门之前把武器放下。没把武器放下的验收官，不是来验收的，是来复制别人的结论的。所以SpecProof 的字典里没有「QA」——它只有「验收官」。

QA 的习惯说「这里没问题」。验收官的习惯说「这里被发现，不被发现也写下，等着你去查」。

一样东西被验收，你能看到它有没有问题。另一样东西被验收，你看不到它有没有问题——它不伪造证据，不掩盖败退。验收官不说「仿佛没问题」，只说「基准过了；头版本挂了，因为——」。


### 9.2 开窗的人

一个窗开着，看见别人的代码。你看到了，你记下了，你不笑；也不哭。验收官不笑。他们笑的是不带感情的：「这块的证据是这一格的。」像法庭上的判决书，每一段都是撕开的评估，没有装饰。

所以 SPECROOF 的前端——所有的那些 StatCard、badge、印章、时间线——都在替那些不希望情绪进入领域的验收官挡住情绪，贴一张「我冷静」的面孔给每一位阅批者。

情绪不进入代码的水晶；但人读过窗缝。


### 9.3 十四种手势（aka 验收官的十四种脸）

跨过这套沉思的最好方式：你如果是一个验收官，你会做十四种不同的手势。所有十四种，都应该有一页对应的证据能指给你看。

| 姿态 | 脸 | 铁证 |
|---|---|---|
| 直视 | 验讫 — 带着印章盖下去的正脸 | `VERIFIED`（证据充足） |
| 挑衅 | 受阻 — 眉头线性推开，嘴角收紧 | `BLOCKED`（发现回纵证据） |
| 试探 | 待议 — 眼角微敛，笔含在指尖 | `NEEDS_REVIEW`（需要人拉） |
| 远眺 | 观望 — 头顶出鞘，鹅侧耳 | `STALE`（太老，没人复验） |
| 冷笑 | 半冷笑 — 脸颊收紧、下颌咬上 | `CANCELLED`（没等你赢，先认输） |
| 关门 | 铁门 — 有人来拉门却拉不动 | `ERROR`（隧道终缩） |
| 默书 | 我记下了 — 这一百行进入了你的肌肉记忆 | `FAILED`（执行未成） |
| 挥去 | 不是完 | `EXPIRED`（做完了，但已被遗忘） |
| 批阅 | 谁的 | `VERIFIED` 上盖回「验讫」——读完了，你批阅了 |
| 原谅 | 等一等 | `STALE` 上盖回——你可以再说；找对了位置再验一次 |
| 推开 | 门轻推一点 | `ERROR` 上盖回——你自动停手；它在回响 |
| 关灯 | 晚安 | `FAILED` 上盖回——今晚不开了；灯就那么停着 |
| 放下笔 | 案子结了 | `VERIFIED` 的按钮落一格；再没人敲你的桌子了 |
| 仍活着 | 习惯 | `STALE` 的反面——「没人处理，不代表死了」|

每一种手势，对应一种数据的真实死亡方式；每一种死法，都是产品本身支持的一种状态。


### 9.4 对话不是一种义务

验收官不向开发商汇报。验收官对着铁说话。如果找不到铁，验收官不写铁名——说「没看到」。

"没看到"不是一种怯懦，是一种尊严。

SpecProof 把这种尊严写进了它的 settings：

- 每个 evidence_type 必填；
- 每个 contract_id 必填；
- 每个 `execution_surface` 必填；
- 每个 `unverified` 如实计入报告。

宁可留一格空，也不把纸揉皱。


### 9.5 如果完整的一卷

不加「代码即法律」、也不加「审视的权利是权利」。这些话太谦。SPECROOF 加一句：

**"证据先于人，人负责证物。"**

证据是先于人的——它在执行之间存在、在合并之前存在、在合意之前存在。人只负责看证据，然后负责决定要不要认它。就是这样。

## 卷十 · 读者抵达之前（Before the Reader Opens This Book）

> 本卷不是一卷关于验收的书——它是给将来读这本书的人预先准备的辞章。
> 如果你已读过卷零到卷九，你已经知道差分是什么、矩阵是什么、证据从哪里开始。
> 那些是常识。卷十讲常识之前的现象——是整段历史还没有开始的时候——人们还没有"验收"这个词的时候——大家是怎么对待代码的。
>
> 那批人不是懒。他们是诚实的。他们不知道"证据"是可以从一块机器流出来的。


### 10.1 你未必读完的

SpecProof 不在你不读的那一刻证明自己。你把这本书从第一个字翻到最后一个字，你读到这里的时候，所有那些实打实的数字、那些早晨的决定、那些被代码行写出来的铁——已经尾波到你眼里。

*这是 SpecProof 最后的 trick——它不是要变成 AI 代码验收行业的默认标准。*
*它只要在你翻完一页的时候、记住铁证是什么、证物是什么、验收是什么。*


### 10.2 六十秒

如果你只读一页：

* 验收不是 ML 模型；是一道工序。
* 60 秒你无法成为验收大师；但是你能记住三个字：
  * **差分**——比对两条跑法、两处答案、两个 ref。
  * **矩阵**——行是契约，列是证据；每一格告诉你一个判断。
  * **印章**——让判断变成可以传递的实体。
* 60 秒你就没法戴上它走开。你会被它跟。你会在看到下一个 Pull Request 的时候，忍不住看底下的 matrix 列表。

那就是 SpecProof 的全部。它试图成为你的习惯；它宁愿在你最疲惫的时候、每一行代码里待着你不排斥的质检点——而不想成为你避开的工具。


### 10.3 验收官不来教你写代码

验收官劝你不再"也许我可以把代码写得更差一点点吧"。
验收官说"我没法。今天写的代码不可收"。
验收官说"我今天没看到"。
验收官说"你的问题在这里—— base_pass_head_fail——铁——你没法绕过去"。

SpecProof 不是完成者；它是不令人舒服的那个见证人。

它这一章不在本书。它在你自己的屏幕里。你只需要按下「新建验证」，然后手放在键盘上——它坐在你的视线前面、你每次看一眼、你都会回想起来：**某句话曾经问我做不做验收官。我选了。**


### 10.4 下一次开机

下次有人问你"你用什么工具做代码验收"——把这个仓库告诉他。**不要说「SpecProof」。直接把路径贴给他。`tests/` 一遍就给他看。让他自己从差分那一刻爱上。**


### 10.5 这本书的最后的字

> 代码写了五十亿行。写下去——没有任何人提前验收过；出了事故救的是人，证据和铁都是所有人付出来的。
> 当差分跑完、矩阵列在你面前的时候——你点的第一个「新建验证」已经被铸成了；它就这么静静地爱你。
>
> 不要感谢书。书只是空空的空间里放着一堆代码——让我们的后来人接住它。


## 卷十一 · 两道门（The Two Doors）

> 本卷讲的不是验收，也不是证据——是**出口**。
> 验收官在屋里站了十卷之后，终于想明白一件事：一扇门如果只能从里面推，也只有从里面推，
> 那它不是门，是墙。门必须朝两个方向都开——朝住户开，朝路过的人开。

### 11.1 第一扇门之前：两条街

一条街用中文写完，一条街用英文写完。两条街巷子一样深、店面一样亮，
但是走的人**看见的招牌不一样**——这不是缺陷，缺陷是同一块招牌上写两种文字，
让谁也读不完整。卷十一立下这么一条规矩：

> **门之内，一座门面是一份语言，两种语言，两个世界；两边的客人进了同一扇门，看见的尽是自己的字。**

在 `apps/web/src/i18n/strings.ts` 里，这一条被写成了一张表：**一个 key、两个 locale、其余零。**
表里的每一句中文，都有一句英文与它逐字对应；表里没有第二种写法——
中文客人看不见英文，英文客人看不见中文，parity 门在 `tests` 里站岗：
哪一边缺了一个 key，门就红给所有人看。不允许任何一位客人走进来时看到「半个世界」。

### 11.2 原生英文，也得说中文

创世记里写的是中文，是因为史官先说了中文。世界书的英文版是后来补的——
不是翻译，是**同一座房子盖了英文的第二面墙**：Scroll 0 到 Scroll 10，逐一成对。
原生英文的运维文档也一样：`CLAUDE.md` 逐段并列、`ARCHITECT_CLAUDE.md` 逐段并列、
`MCP_GUIDE.zh.md` 逐节镜像。**英文原生的内容也全部翻成了中文**——
不是因为中文更高级，而是因为在门里，两种语言都是母语。

诚实边界里写过：**能切 ≠ 都翻了。** 旧页面正文仍是中文原生、eng 文档仍有按批推进的队列——
这些都不在本书之中撒谎。卷十一把「诚实边界」写进正文：门开着，不等于每一个厅都已经双语布置完；
没布置完的，宁可挂一块写着「中文陈列」的牌子，也不让雾混进去。

### 11.3 第二扇门：橱窗

这一卷还讲一种更外向的门——街上的橱窗。`xiaodernan.github.io` 是验收官的门面橱窗；
橱窗里挂的是**本仓库最新的成果**，不是上个月的照片。

> 橱窗自动更新，但不亲手推送。SpecProof 只生产一件事实材料：`artifacts/portfolio-data/`
> （`.github-sync.json`、`latest.md`、`products.json`），由 portfolio 自己定时取，
> 或由人点一下同步——本仓库绝不向 portfolio 仓库推任何东西，绝不携带凭据，绝不现场编造。
> 大版本才挂新件、低频更新——这样橱窗永远值得看一眼，不忠于刷量。

橱窗不古板：它只陈列，不替 portfolio 决定要挂什么、几号换——**产出最新、消费方决定展示**。
这是门的第二道礼仪：Producer owns facts; the window owns the wearing.

### 11.4 门开了以后

两道门都开了以后，房间里没有什么变——差分照跑，矩阵照列，印章照盖。
变的是门里的灯，和街上知道有这扇门的人。

下一次有人问「**这个世界里有中文，也有英文；有屋里的工序，也有街上的橱窗——你先要看哪一个？**"
——验收官会说：「先推门，随便哪一扇。门里的铁是同一炉。」

## 卷十二 · 墙内的展厅（Inside: The Hall of Exhibits）

> 卷十一讲了两扇门：门朝里，门朝外。卷十二讲的是门已开之后、屋子里多出来的那间屋——
> 验收官在墙上钉了十二枚铁证。

### 12.1 展厅为何而立

SpecProof 里最古老的习惯是「记下来」——从差分实验的第一天起，每个数字都落进账本。
可是数字落进了账本，墙上的眼泪却没有落进屋子里来。展品发生时没有人拍照，
它们只是按日期躺平。于是铁证博物馆立了起来：把那些已经在 git log 里躺平的数字，
一件一件搬回它们真正发生时的姿势。

十二件展品，没有装饰性指标，没有「影响力星级」。**展签上的锚点就是分量**——
你可以按 git show c75a0ef 去看那一次巡览（#1677）是怎么交付的；
你可以按 git log --grep "#1689" 去看那个差分是怎么抓住 AUTH-01 的。
展厅不证明什么；展厅只是把现场原样开了灯。

### 12.2 墙内还是墙外

展厅在墙内——用户打开左侧「质量与证据」就能看见它。
展厅也在墙外——它索引的每一枚锚点都能在墙外翻出来对账。

这是一种双向的美学：**在墙内看见墙外，墙内外共享同一炉火。**
正史（卷零到卷十一）之所以物化成 UI，不是为了炫耀，是为了替铁证立一卷好查的入口——
差分照跑，矩阵照列，印章照盖，展厅等你来对。

### 12.3 谁会走进展厅

展厅没有固定开厅时间，因为**每一个入口都是它的开厅时间**。会有人专门为此而来：

* **审计官**：先看卷八（The Chronicler's Vigil）里说的「账本不撒谎」，再逐件核对锚点。
* **新手**：先走巡览盖章（卷一），再读展厅里的第 V 件展品（那个炸掉构建的 CI 类），
  之后会对自己的第一条 CSS 选择器更谨慎。
* **未来的史官**：在某一天对某一件展品皱眉，然后开始第十二件的续写。
  展厅是接力赛的接力棒位置。

SpecProof 的一些事物是为了当下而设计的，另一些——比如下一卷——是为了给到每一个读者
的。

### 12.4 通向下一卷

路线图未完：IDE 集成（6.1）、可观测默认开启（5.3）、部署形态（5.4）——它们都还写在
PRODUCT_ROADMAP.md 里，等下一个 commit。卷十一讲门，卷十二讲厅，下一卷该讲什么？

*卷十二的答案留在它的尽头之后。*

它不会停在「铁证之书」里；它会在下一个 Pull Request 里落定——因为界面已经准备好
接住它：路由已开，锚点已准，史官不缺笔，缺的是下一件事被写下来。

## 卷十三 · 史官与缓存（The Chronicler and the Cache）

> 卷三讲的是缓存作为一种教义；卷十三讲的是**缓存作为一种修身**——当史官把「不要动那段稳定文本」
> 写进本能里的时候，缓存就不再是一个开关，而是一种克制。

### 13.1 先实测，再立言

史官不写「缓存命中率很高」。史官写：「2026-11 实测，_JUNIT_GENERATION_PROMPT 的稳定前缀在 wkapi.pro
上重复命中率 96.5%（#1645）；去掉稳定前缀的字节数，#1679 与 #1681 的收发数据显示，同样的变量尾巴、
换不同的变量值，命中率振荡在 75.2%–84%。」

语言确实的句子长一点，但每一个数字都落在 git 里。缓存是一个把人逼诚实的东西——
它不相信你「以为自己稳定」，它只看前缀是不是真的一字不差。

### 13.2 那 2272 字节

_JUNIT_GENERATION_PROMPT 的稳定前缀是 ~567 tokens，写下它的人没有人性化润色它——
栏位的顺序、换行的数量、注释的位置，全部是为缓存服务的。改动一个空格，就是改动缓存键。
把美学献给机器，机器回报你成本下降、反例持续产出。

AI 开发者有几种对待稳定前缀的姿势：偷偷扩写、悄悄缩短、重新排序、精简注释。
史官把所有「只增不减」的缓存纪律记在本子上：**能写死的，就写死；会漂的，就钉住**——
把变量统统往后挪；把不变的部分挖好，打成血统稳定的大砖。

### 13.3 双车道之后

第 1644 号与第 1663 号之后，verify 的两个车道（legacy lane 与 policy lane）终于都开着
`stream=True + include_usage=True`——网关从此有 cached_tokens 可报，命中率从此可以落进
used_tokens 的账本，而不再像过去那样一周一边打的问号一周一边打的句号。

#1681 把这一课立成了铁律：**所有真实调用必须走流式车道**，否则供应商的缓存到底节省了多少
token 都取决于「这次网关心情好不好」。流式不是美学，是考核。

### 13.4 缓存也有它的宿命

#1679 与 #1681 各自测量过：**wkapi 的 cached_tokens 可能返回 null**——它按 prompt 字节算缓存，
换字节就重算。即使前缀一字不差，遇到网关未上报或者 prompt 略有出入，指标就
"断崖"。

所以缓存命中率从来不是一个契约值。缓存是提示，不是判决；记录是结论，不是猜测。
SpecProof 把「网关未上报时当场显式写 null」写进了 Usage 面板（#1646/#1704）——
宁可断档，也不画假点。这就是史官与缓存同行的全部教义。

### 13.5 双语的意义已经变了

卷十一立「一个 key 两个 locale」之后，prompt 被分成两种语言的两份稳定前缀——这既是额外的
缓存可能性，也是一条更难绕开的纪律：中英文都被钉住，换一种语言就等于换一块砖。
你可以偷偷改英文版并期望没人发现；中英双轨的提交审核里，任何一版的漂移都指向同一个 PR。

缓存是一面镜子：你对它有多老实，你的 prompt 就有多有效率。
