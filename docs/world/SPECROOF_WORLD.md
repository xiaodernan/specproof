## 卷零 · 创世之炉

世人写代码，代码又写代码。AI 把箭射入天空，不问谁将拾箭。

在创世的第一天，验收官立了这一条铁律：**凡欲过此炉者，证据先行；证据不成，不许谈白
收不收。** AI 的手可以写，验收官的眼必看——眼不看的，机器代看；机器不能单判，还有人来签。

于是第一座殿被盖起来，是**差分炉**（`experiments/differential.py` 等族）：
把同一段需求分别编入 base 与 head，在同一个牢笼（Docker 沙箱，`docker_sandbox.py`）
里分别点火，看火苗往哪边倒。火往回烧的是基线的光荣，往前烧的是头上的伤口。
一正一反，落在同一块铁上，无人可抵赖。

差分炉里最常见的名字叫 **`base_pass_head_fail`**——基线过，头版本挂。
世人称此为"铁"。炉火正旺之际，护炉者手痒，想把探针（probe）的结果说成铁，
差点又被点掉了——这是卷一里讲的另一段公案（见"卷一 · 探针防伪的九次红灯"）。

## 卷一 · 铁证、矩阵与审判庭

### 1.1 铁证五等

SpecProof 的证据分五等，从下至上等级越高、越硬：

| 等级 | 名称 | 例证 | 铁度 |
|---|---|---|---|
| 五等 | `static_analysis` | 静态分析、正则命中 | 可信可疑 |
| 四等 | `java_source_diff` | Java 源码差分（没行任何代码） | 半信半疑 |
| 三等 | `constitution_check` / `probe_differential` | 规范检查 / 探针差分 | Semi-鉄 |
| 二等 | `differential_execution` | 基线/头版本各执行一次的对比 | 铁证前奏 |
| 一等 | `base_pass_head_fail` | 基线过、头版挂 | **铁** |

证据的等级由铁（差分执行）定，不由口才定。矩阵（`apps/web/src/pages/Matrix.tsx`）上
每一格停在五等中的一等上，并把执行面（`execution_surface`：
`sandbox` / `host` / `none`）明明白白刻写进格子。

### 1.2 审判庭（Review Court）

一间不准 AI 单判的法庭。对抗式流程：

```
检察官出卷 → 辩护人逐项辩 → 裁判席按"铁证优先原则"定谳
```

辩护人可以在卷上写"这可能是误报"，但辩护人写得再动听，也改不了
`base_pass_head_fail` 这种火一样的事实。裁判席由 `specproof_review_court`（pin 在
`tests/unit/test_matrix_pure.py` 与 `test_matrix_policy.py` 上的政策表）定夺——
**模型只提供辩护，不提供刑名**，这是卷一最重的一句话。

> 公案 · **probe_defense 的逆流（#1638 族）**：
> 探针（probe）的本意是好的，可人心不稳。差点把探针结果当成"此错误必存在"，被静态分析
> 顶上去当了铁证。后来铁证的名单被钉死——不属于差分的，无论多像，也不入一等铁。

### 1.3 反例生成

验收不是站在旁边点头，是主动去找死因。编译器（`agent/nodes/generate_counterexamples.py`）
替每个 finding 写一份能复现得了的小测试：基线绿、头版红——红得像亲眼看见。
"能装进卷宗的 bug，才是验收官认得的 bug。"——差分炉的铁律。

## 卷二 · 双端相望：验收官与他的书记官

### 2.1 书记官的笔

书记官（前端）的书写有规矩：

- 不编造：凡字段为空写 `（未提供）`，不写"没有"而假装有铁证。
- 不做判：AI 解读只在旁边注释，裁决依然由矩阵说。
- 不滚动：阶段时间线（StageTimeline）缺少时间戳的节点**如实列在下方**并写明"未进入条形区——诚实省略"；它不编造坐标。
- 不乱叫：severity 词表永远是 `BLOCKER / MAJOR / MINOR / PASS`，从不凑热闹。

这些都能在 `apps/web/src/pages/JobDetail.tsx`、`StageTimeline.tsx`、`epicCertificate.ts`
里对上号。

### 2.2 打印即盖章

print.css 不只是打印样式，它是行政规范：证据级 A4 版面、机关文书格式、批注与签章框。
打印机吐出的每一页，都要能摆上签字桌。

### 2.3 复制与分享是评审的第二语言

评审者不在系统里，但评审意见必须进系统。所以每个验收页都有「复制 Markdown 摘要」
与「复制史诗纪要」两枚钮——前者给贴吧论坛，后者给史官讲故事。两枚钮装的都是真货，
没有一枚是空包装。

## 卷三 · 缓存圣断：给算力修庙

### 3.1 非流与流的世纪之战

起初，每一桩查验都走非流车道——网关的仪表盘从此日夜显示"非流"，
缓存命中率像煤气灶上不点火的粥干烧。案子翻了几十桩之后，史官发现
（#1644/#1645）：

> 问题不在于"不求流取"，而在于**请求长得不一样、却假装是同一道题**。
> 非流与流不是两个世界；是同一个箴言在两种包装里。

于是立了**双车道流式统一令**（#1663）：`chat()` 与 `chat_stream()` 双双
`stream=True + include_usage`；`_parse_usage` 把 `prompt_tokens_details.cached_tokens`
映射为 `prompt_cache_hit_tokens`；计费档按 0.1× 给命中计价。
从此网关仪表盘再没有"非流"两个字。

### 3.2 前缀即圣火

圣断军令：**稳定前缀在前，可变内容在后**。一段提示词不是散文，是一个缓存键：

```
STABLE PREFIX FIRST → VARIABLE DATA LAST
```

`_JUNIT_GENERATION_PROMPT` 的前缀 2272 字节，稳如磐石；
第一次 42.1s，第四次 9.1s，hit=4736/4906，96.5%——此为 #1645 记下的最秀之役。

中段插变量、静态尾句压尾——会杀缓存，是结构性犯罪（#1668 已点名：
review_court 的 candidates_json、compile_contracts 的 spec/context、parser 的 spec_text，
三处的 rewrite H 已依此立式：静态指令 + persona 整体在前，变量一律由调用方追加在尾部）。

### 3.3 A/B 与不斩之罪

#1668 的复核：同 prompt 字节复读两种排序都命中 87.5% / 99.98%；换变量后两种排序
wkapi 今日均报 `cached=None`——**两组数据不一致，如实并列，至今未被裁决**。
世人记住：这不是"修好了"，这是"暂时测不出来"——记录不猜；美酒酿得好与不好，
史官都照单全记。

### 3.4 语义缓存：把重复的一千次呼吸只写一本

`specproof_semcache:*`（Redis 分布式）缓存机制：sha256 键、50ms 双超时、
fail-open、evidence 类硬拒绝（court/counterexample/contract_compile 永不进缓存）。
命中省算力；未命中照旧老老实实算。凡属于"再算一遍也不会变结果"的，
缓存叫它"不必重验"。

## 卷四 · 军阵：钢铁长城与不死的门

### 4.1 四个服务，一个集团军

| 服务 | 兵种 | 职责 |
|---|---|---|
| `config-server` | 军需官 | Spring Cloud Config；分布式配置一本统管；`optional:configserver:` 让没军需也不饿死 |
| `discovery-server` | 登记册 | Eureka Server；`specproof-gateway` 一键入册 |
| `gateway` | 边关 | 路由表即法律（route-isomorphism gate 兜底）、rate limit、breaker、`/actuator/refresh` |
| `control-plane` | 内政 | 租户、作业门面、Webhook；业务真理之源 |

网关的路由表里，`/**` 的算法是个接盘侠——谁都不归它管；它只是把说好的戏排完戏给别人唱。
谁接到哪一出戏，在表里明写着；谁抢了别人的路由，`route-isomorphism gate` 当场喊停——
**"missingServices=[]"那天，它就是在宣告集团军团结**。

### 4.2 断路器如关城闸

Resilience4j 断路器（`specproof-edge` / `specproof-control-plane` 两个实例），
slidingWindow 10、minimumCalls 5、failureRatio 50%、half-open 3 次。
**某一晚**，史官把 control-plane 这条路故意打死：

```
req 1..4: state=closed
req 5..12: state=open   →  "edge": "circuit-open"
```

十二次请求，五次翻开，`specproof_control_plane` 铁着脸把表亮出来：
**断路器没有偷偷 recovery，也没有悄悄说好家伙——它就是开的。**

### 4.3 RabbitMQ 不在键盘上敲门

Rabbit 是可选总线（`specproof.observability.events` 交换器，六键事件，默认关）。
当没人敲门的时候，specproof-gateway 的 `/actuator/health` 不应 503——
Rabbit 已排除出健康指标（同构纪律：Redis 同款处理），**没敲的门不算关城**。

## 卷五 · 史官纪要：一笔不删、一笔不增

### 5.1 账本

`docs/operations/DEEP_OPTIMIZATION_PLAN.md` 是这座城的编年史。每一笔记：

## 卷六 · 人物志

### 验收官

不是打字的 AI，也不是按鼠标的 PD，而是把"我不相信"写成"我验一下"的那个人。
验收官的基本功：会看火焰颜色、会读铁证纹理、知道什么时候该喊停。

### 证人（Witness）

`gpt-6-sol`（wkapi.pro 真实接入，流式车道）、`claude-*`（备用）。证人讲证词，
不替验收官定罪。证人万一说错了证词，验收官不砸证人——证人有他自己的一份工分，
铁证才是判官。

### 书记官

每次验收都带一本书记官走进会场：复制按钮（Markdown 摘要 / 史诗纪要）、
"打印此卷"、阶段时间线、缓存健康面板——这本笔记是验收官的副武器，它不裁决，它只记。

### 史官

拿 `#1620`–`#1675` 一条一条对着 git log 核对。账本如果是假的，他先翻车。
所以他宁可多说"还没测"——**说还没测有错，从没骗过**。

## 卷八 · 史官守夜（The Chronicler's Vigil）

> 此卷直写本书的诞生——不是旁观者，而是参与者。SpecProof 在守夜里学会了一件事：
> 每一扇新门打开之前，先有一张地图；每一张地图，都是铁证刻出来的。
>
> 本卷全部发生于 2026-11-14：这一夜 SpecProof 学会了把自己的历史写进作品内部。

### 8.1 半日之间的大推进

| 时辰 | 事 |
|---|---|
| 清晨 | 「史诗 · The Chronicles of SpecProof」页面落成（`#1675`）——六卷竹简式排版， Serif 中文，玉 medallion，红色印章，把本项目真实铁证作为章节的「史官细则」锚点 |
| 辰时 | 「铁证之书 · SpecProof 创世记」世界观正史开始动笔（`#1676`）——本书是它的续 |
| 巳时 | 巡览模块「巡览 · The Grand Tour of SpecProof」落成（`#1677`）——六卷游记，每一桩真实的查验证都必须由用户自己按一次手印才能算完成，盖满六卷获得「验讫」印章 |
| 午后 | Spring Cloud 微服务全链路实测：config-server / discovery-server（Eureka）各自启动 UP，gateway 注册自己、反向代理、断路器、/actuator/refresh 见证人（`specproof_edge_config_refresh_events_total` 0→1） |
| 黄昏 | 并轨车道的 token 级 usage-ledger 顺利接手并包完 3 个红 contract 测试，17/17 全绿 |

### 8.2 井底与天星

世上最难写进历史的那一页，是「史官发现自己的笔杆比他的作品更重的那一天」。

SpecProof 的史官这一夜学会了同时做三件事：

1. **看住没人看的角落**——连 RabbitMQ 健康 indicator 这个「总线应不应答」的低气压信号都要诚实记账（#1674 本节：gateway 的 Rabbit health indicator 关掉了，因为 broker 对 edge 是可选的、不是可选项——这不变红为绿，只补了边缘拓扑的如实状态）；
2. **不编造**——场景里的每一处「已发生」都有 git commit 号作为「史官细则」的脚注；凡编不出来的，就是编不出来，写「未完成」而不是「已完成」；
3. **让下一位史官走进来不发愣**——`#1676` 与 `#1677` 把 SpecProof 的真实实验过程、缺陷、教训、限制都以故事形式钉在里侧：`#1638` 探针锚定、`#1668` A/B 并列记录、`#1672` SSE `done` 帧丢失的教训。每一次翻一本新册，下一个读者都能问自己：这一章的铁证在哪里？

### 8.3 世界观落成的意义

「史诗」和「世界观」不是装饰。SpecProof 的诞生是从为 AI 时代写验收的人开始的——
**这个世界的主人公不是 AI，是人。** 人写代码也好、人验代码也好，AI 可以讲故事，
但愿烧铁证的炉子不是 AI 看管的，而是人。

这一卷也替读者记了一句话：

> 凡欲验收者，先验自己；凡欲入史者，先亮铁证；
> 铁证面前，不信为智，信为诚，不测为愚。
