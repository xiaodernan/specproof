## 卷零 · 创世之炉

世人写代码，代码又写代码。AI 把箭射入天空，不问谁将拾箭。

在创世的第一天，验收官立了这一条铁律：**凡欲过此炉者，证据先行；证据不成，不许谈白
收不收。** AI 的手可以写，验收官的眼必看——眼不看的，机器代看；机器不能单判，还有人来签。

于是第一座殿被盖起来，是**差分炉**（`experiments/differential.py` 等族）：
把同一段需求分别编入 base 与 head，在同一个牢笼（Docker 沙箱，`docker_sandbox.py`）
里分别点火，看火苗往哪边倒。火往回烧的是基线的光荣，往前烧的是头上的伤口。
一正一反，落在同一块铁上，无人可抵赖。

差分炉里最常见的名字叫 **`base_pass_head_fail`**——基线过，头版本挂。
世人称此为"铁"。炉火正旺之际，护炉者手痒，想把探针（probe）的结果说成铁，
差点又被点掉了——这是卷一里讲的另一段公案（见"卷一 · 探针防伪的九次红灯"）。

## 卷一 · 铁证、矩阵与审判庭

### 1.1 铁证五等

SpecProof 的证据分五等，从下至上等级越高、越硬：

| 等级 | 名称 | 例证 | 铁度 |
|---|---|---|---|
| 五等 | `static_analysis` | 静态分析、正则命中 | 可信可疑 |
| 四等 | `java_source_diff` | Java 源码差分（没行任何代码） | 半信半疑 |
| 三等 | `constitution_check` / `probe_differential` | 规范检查 / 探针差分 | Semi-鉄 |
| 二等 | `differential_execution` | 基线/头版本各执行一次的对比 | 铁证前奏 |
| 一等 | `base_pass_head_fail` | 基线过、头版挂 | **铁** |

证据的等级由铁（差分执行）定，不由口才定。矩阵（`apps/web/src/pages/Matrix.tsx`）上
每一格停在五等中的一等上，并把执行面（`execution_surface`：
`sandbox` / `host` / `none`）明明白白刻写进格子。

### 1.2 审判庭（Review Court）

一间不准 AI 单判的法庭。对抗式流程：

```
检察官出卷 → 辩护人逐项辩 → 裁判席按"铁证优先原则"定谳
```

辩护人可以在卷上写"这可能是误报"，但辩护人写得再动听，也改不了
`base_pass_head_fail` 这种火一样的事实。裁判席由 `specproof_review_court`（pin 在
`tests/unit/test_matrix_pure.py` 与 `test_matrix_policy.py` 上的政策表）定夺——
**模型只提供辩护，不提供刑名**，这是卷一最重的一句话。

> 公案 · **probe_defense 的逆流（#1638 族）**：
> 探针（probe）的本意是好的，可人心不稳。差点把探针结果当成"此错误必存在"，被静态分析
> 顶上去当了铁证。后来铁证的名单被钉死——不属于差分的，无论多像，也不入一等铁。

### 1.3 反例生成

验收不是站在旁边点头，是主动去找死因。编译器（`agent/nodes/generate_counterexamples.py`）
替每个 finding 写一份能复现得了的小测试：基线绿、头版红——红得像亲眼看见。
"能装进卷宗的 bug，才是验收官认得的 bug。"——差分炉的铁律。

## 卷二 · 双端相望：验收官与他的书记官

### 2.1 书记官的笔

书记官（前端）的书写有规矩：

- 不编造：凡字段为空写 `（未提供）`，不写"没有"而假装有铁证。
- 不做判：AI 解读只在旁边注释，裁决依然由矩阵说。
- 不滚动：阶段时间线（StageTimeline）缺少时间戳的节点**如实列在下方**并写明"未进入条形区——诚实省略"；它不编造坐标。
- 不乱叫：severity 词表永远是 `BLOCKER / MAJOR / MINOR / PASS`，从不凑热闹。

这些都能在 `apps/web/src/pages/JobDetail.tsx`、`StageTimeline.tsx`、`epicCertificate.ts`
里对上号。

### 2.2 打印即盖章

print.css 不只是打印样式，它是行政规范：证据级 A4 版面、机关文书格式、批注与签章框。
打印机吐出的每一页，都要能摆上签字桌。

### 2.3 复制与分享是评审的第二语言

评审者不在系统里，但评审意见必须进系统。所以每个验收页都有「复制 Markdown 摘要」
与「复制史诗纪要」两枚钮——前者给贴吧论坛，后者给史官讲故事。两枚钮装的都是真货，
没有一枚是空包装。

## 卷三 · 缓存圣断：给算力修庙

### 3.1 非流与流的世纪之战

起初，每一桩查验都走非流车道——网关的仪表盘从此日夜显示"非流"，
缓存命中率像煤气灶上不点火的粥干烧。案子翻了几十桩之后，史官发现
（#1644/#1645）：

> 问题不在于"不求流取"，而在于**请求长得不一样、却假装是同一道题**。
> 非流与流不是两个世界；是同一个箴言在两种包装里。

于是立了**双车道流式统一令**（#1663）：`chat()` 与 `chat_stream()` 双双
`stream=True + include_usage`；`_parse_usage` 把 `prompt_tokens_details.cached_tokens`
映射为 `prompt_cache_hit_tokens`；计费档按 0.1× 给命中计价。
从此网关仪表盘再没有"非流"两个字。

### 3.2 前缀即圣火

圣断军令：**稳定前缀在前，可变内容在后**。一段提示词不是散文，是一个缓存键：

```
STABLE PREFIX FIRST → VARIABLE DATA LAST
```

`_JUNIT_GENERATION_PROMPT` 的前缀 2272 字节，稳如磐石；
第一次 42.1s，第四次 9.1s，hit=4736/4906，96.5%——此为 #1645 记下的最秀之役。

中段插变量、静态尾句压尾——会杀缓存，是结构性犯罪（#1668 已点名：
review_court 的 candidates_json、compile_contracts 的 spec/context、parser 的 spec_text，
三处的 rewrite H 已依此立式：静态指令 + persona 整体在前，变量一律由调用方追加在尾部）。

### 3.3 A/B 与不斩之罪

#1668 的复核：同 prompt 字节复读两种排序都命中 87.5% / 99.98%；换变量后两种排序
wkapi 今日均报 `cached=None`——**两组数据不一致，如实并列，至今未被裁决**。
世人记住：这不是"修好了"，这是"暂时测不出来"——记录不猜；美酒酿得好与不好，
史官都照单全记。

### 3.4 语义缓存：把重复的一千次呼吸只写一本

`specproof_semcache:*`（Redis 分布式）缓存机制：sha256 键、50ms 双超时、
fail-open、evidence 类硬拒绝（court/counterexample/contract_compile 永不进缓存）。
命中省算力；未命中照旧老老实实算。凡属于"再算一遍也不会变结果"的，
缓存叫它"不必重验"。

## 卷四 · 军阵：钢铁长城与不死的门

### 4.1 四个服务，一个集团军

| 服务 | 兵种 | 职责 |
|---|---|---|
| `config-server` | 军需官 | Spring Cloud Config；分布式配置一本统管；`optional:configserver:` 让没军需也不饿死 |
| `discovery-server` | 登记册 | Eureka Server；`specproof-gateway` 一键入册 |
| `gateway` | 边关 | 路由表即法律（route-isomorphism gate 兜底）、rate limit、breaker、`/actuator/refresh` |
| `control-plane` | 内政 | 租户、作业门面、Webhook；业务真理之源 |

网关的路由表里，`/**` 的算法是个接盘侠——谁都不归它管；它只是把说好的戏排完戏给别人唱。
谁接到哪一出戏，在表里明写着；谁抢了别人的路由，`route-isomorphism gate` 当场喊停——
**"missingServices=[]"那天，它就是在宣告集团军团结**。

### 4.2 断路器如关城闸

Resilience4j 断路器（`specproof-edge` / `specproof-control-plane` 两个实例），
slidingWindow 10、minimumCalls 5、failureRatio 50%、half-open 3 次。
**某一晚**，史官把 control-plane 这条路故意打死：

```
req 1..4: state=closed
req 5..12: state=open   →  "edge": "circuit-open"
```

十二次请求，五次翻开，`specproof_control_plane` 铁着脸把表亮出来：
**断路器没有偷偷 recovery，也没有悄悄说好家伙——它就是开的。**

### 4.3 RabbitMQ 不在键盘上敲门

Rabbit 是可选总线（`specproof.observability.events` 交换器，六键事件，默认关）。
当没人敲门的时候，specproof-gateway 的 `/actuator/health` 不应 503——
Rabbit 已排除出健康指标（同构纪律：Redis 同款处理），**没敲的门不算关城**。

## 卷六 · 人物志

### 验收官

不是打字的 AI，也不是按鼠标的 PD，而是把"我不相信"写成"我验一下"的那个人。
验收官的基本功：会看火焰颜色、会读铁证纹理、知道什么时候该喊停。

### 证人（Witness）

`gpt-6-sol`（wkapi.pro 真实接入，流式车道）、`claude-*`（备用）。证人讲证词，
不替验收官定罪。证人万一说错了证词，验收官不砸证人——证人有他自己的一份工分，
铁证才是判官。

### 书记官

每次验收都带一本书记官走进会场：复制按钮（Markdown 摘要 / 史诗纪要）、
"打印此卷"、阶段时间线、缓存健康面板——这本笔记是验收官的副武器，它不裁决，它只记。

### 史官

拿 `#1620`–`#1675` 一条一条对着 git log 核对。账本如果是假的，他先翻车。
所以他宁可多说"还没测"——**说还没测有错，从没骗过**。

## 卷八 · 史官守夜（The Chronicler's Vigil）

### 8.2 井底与天星

世上最难写进历史的那一页，是「史官发现自己的笔杆比他的作品更重的那一天」。

SpecProof 的史官这一夜学会了同时做三件事：

1. **看住没人看的角落**——连 RabbitMQ 健康 indicator 这个「总线应不应答」的低气压信号都要诚实记账（#1674 本节：gateway 的 Rabbit health indicator 关掉了，因为 broker 对 edge 是可选的、不是可选项——这不变红为绿，只补了边缘拓扑的如实状态）；
2. **不编造**——场景里的每一处「已发生」都有 git commit 号作为「史官细则」的脚注；凡编不出来的，就是编不出来，写「未完成」而不是「已完成」；
3. **让下一位史官走进来不发愣**——`#1676` 与 `#1677` 把 SpecProof 的真实实验过程、缺陷、教训、限制都以故事形式钉在里侧：`#1638` 探针锚定、`#1668` A/B 并列记录、`#1672` SSE `done` 帧丢失的教训。每一次翻一本新册，下一个读者都能问自己：这一章的铁证在哪里？

### 8.3 世界观落成的意义

「史诗」和「世界观」不是装饰。SpecProof 的诞生是从为 AI 时代写验收的人开始的——
**这个世界的主人公不是 AI，是人。** 人写代码也好、人验代码也好，AI 可以讲故事，
但愿烧铁证的炉子不是 AI 看管的，而是人。

这一卷也替读者记了一句话：

> 凡欲验收者，先验自己；凡欲入史者，先亮铁证；
> 铁证面前，不信为智，信为诚，不测为愚。

## 卷九 · 印章与窗（The Seal and the Window）

> 此卷若真，是验收官自己的内心独白；若假，也是门看客来玩铁。
> 验收不是手拿得起来的东西——它是先把自己摆进去，再摆进去别人交出的东西。


### 9.1 卸下身上所有的装备是一种技术

来做验收的人，进门之前把武器放下。没把武器放下的验收官，不是来验收的，是来复制别人的结论的。所以SpecProof 的字典里没有「QA」——它只有「验收官」。

QA 的习惯说「这里没问题」。验收官的习惯说「这里被发现，不被发现也写下，等着你去查」。

一样东西被验收，你能看到它有没有问题。另一样东西被验收，你看不到它有没有问题——它不伪造证据，不掩盖败退。验收官不说「仿佛没问题」，只说「基准过了；头版本挂了，因为——」。


### 9.2 开窗的人

一个窗开着，看见别人的代码。你看到了，你记下了，你不笑；也不哭。验收官不笑。他们笑的是不带感情的：「这块的证据是这一格的。」像法庭上的判决书，每一段都是撕开的评估，没有装饰。

所以 SPECROOF 的前端——所有的那些 StatCard、badge、印章、时间线——都在替那些不希望情绪进入领域的验收官挡住情绪，贴一张「我冷静」的面孔给每一位阅批者。

情绪不进入代码的水晶；但人读过窗缝。


### 9.3 十四种手势（aka 验收官的十四种脸）

跨过这套沉思的最好方式：你如果是一个验收官，你会做十四种不同的手势。所有十四种，都应该有一页对应的证据能指给你看。

| 姿态 | 脸 | 铁证 |
|---|---|---|
| 直视 | 验讫 — 带着印章盖下去的正脸 | `VERIFIED`（证据充足） |
| 挑衅 | 受阻 — 眉头线性推开，嘴角收紧 | `BLOCKED`（发现回纵证据） |
| 试探 | 待议 — 眼角微敛，笔含在指尖 | `NEEDS_REVIEW`（需要人拉） |
| 远眺 | 观望 — 头顶出鞘，鹅侧耳 | `STALE`（太老，没人复验） |
| 冷笑 | 半冷笑 — 脸颊收紧、下颌咬上 | `CANCELLED`（没等你赢，先认输） |
| 关门 | 铁门 — 有人来拉门却拉不动 | `ERROR`（隧道终缩） |
| 默书 | 我记下了 — 这一百行进入了你的肌肉记忆 | `FAILED`（执行未成） |
| 挥去 | 不是完 | `EXPIRED`（做完了，但已被遗忘） |
| 批阅 | 谁的 | `VERIFIED` 上盖回「验讫」——读完了，你批阅了 |
| 原谅 | 等一等 | `STALE` 上盖回——你可以再说；找对了位置再验一次 |
| 推开 | 门轻推一点 | `ERROR` 上盖回——你自动停手；它在回响 |
| 关灯 | 晚安 | `FAILED` 上盖回——今晚不开了；灯就那么停着 |
| 放下笔 | 案子结了 | `VERIFIED` 的按钮落一格；再没人敲你的桌子了 |
| 仍活着 | 习惯 | `STALE` 的反面——「没人处理，不代表死了」|

每一种手势，对应一种数据的真实死亡方式；每一种死法，都是产品本身支持的一种状态。


### 9.4 对话不是一种义务

验收官不向开发商汇报。验收官对着铁说话。如果找不到铁，验收官不写铁名——说「没看到」。

"没看到"不是一种怯懦，是一种尊严。

SpecProof 把这种尊严写进了它的 settings：

- 每个 evidence_type 必填；
- 每个 contract_id 必填；
- 每个 `execution_surface` 必填；
- 每个 `unverified` 如实计入报告。

宁可留一格空，也不把纸揉皱。


### 9.5 如果完整的一卷

不加「代码即法律」、也不加「审视的权利是权利」。这些话太谦。SPECROOF 加一句：

**"证据先于人，人负责证物。"**

证据是先于人的——它在执行之间存在、在合并之前存在、在合意之前存在。人只负责看证据，然后负责决定要不要认它。就是这样。

## 卷十 · 读者抵达之前（Before the Reader Opens This Book）

> 本卷不是一卷关于验收的书——它是给将来读这本书的人预先准备的辞章。
> 如果你已读过卷零到卷九，你已经知道差分是什么、矩阵是什么、证据从哪里开始。
> 那些是常识。卷十讲常识之前的现象——是整段历史还没有开始的时候——人们还没有"验收"这个词的时候——大家是怎么对待代码的。
>
> 那批人不是懒。他们是诚实的。他们不知道"证据"是可以从一块机器流出来的。


### 10.1 你未必读完的

SpecProof 不在你不读的那一刻证明自己。你把这本书从第一个字翻到最后一个字，你读到这里的时候，所有那些实打实的数字、那些早晨的决定、那些被代码行写出来的铁——已经尾波到你眼里。

*这是 SpecProof 最后的 trick——它不是要变成 AI 代码验收行业的默认标准。*
*它只要在你翻完一页的时候、记住铁证是什么、证物是什么、验收是什么。*


### 10.2 六十秒

如果你只读一页：

* 验收不是 ML 模型；是一道工序。
* 60 秒你无法成为验收大师；但是你能记住三个字：
  * **差分**——比对两条跑法、两处答案、两个 ref。
  * **矩阵**——行是契约，列是证据；每一格告诉你一个判断。
  * **印章**——让判断变成可以传递的实体。
* 60 秒你就没法戴上它走开。你会被它跟。你会在看到下一个 Pull Request 的时候，忍不住看底下的 matrix 列表。

那就是 SpecProof 的全部。它试图成为你的习惯；它宁愿在你最疲惫的时候、每一行代码里待着你不排斥的质检点——而不想成为你避开的工具。


### 10.3 验收官不来教你写代码

验收官劝你不再"也许我可以把代码写得更差一点点吧"。
验收官说"我没法。今天写的代码不可收"。
验收官说"我今天没看到"。
验收官说"你的问题在这里—— base_pass_head_fail——铁——你没法绕过去"。

SpecProof 不是完成者；它是不令人舒服的那个见证人。

它这一章不在本书。它在你自己的屏幕里。你只需要按下「新建验证」，然后手放在键盘上——它坐在你的视线前面、你每次看一眼、你都会回想起来：**某句话曾经问我做不做验收官。我选了。**


### 10.4 下一次开机

下次有人问你"你用什么工具做代码验收"——把这个仓库告诉他。**不要说「SpecProof」。直接把路径贴给他。`tests/` 一遍就给他看。让他自己从差分那一刻爱上。**


### 10.5 这本书的最后的字

> 代码写了五十亿行。写下去——没有任何人提前验收过；出了事故救的是人，证据和铁都是所有人付出来的。
> 当差分跑完、矩阵列在你面前的时候——你点的第一个「新建验证」已经被铸成了；它就这么静静地爱你。
>
> 不要感谢书。书只是空空的空间里放着一堆代码——让我们的后来人接住它。


## 卷十一 · 两道门（The Two Doors）

> 本卷讲的不是验收，也不是证据——是**出口**。
> 验收官在屋里站了十卷之后，终于想明白一件事：一扇门如果只能从里面推，也只有从里面推，
> 那它不是门，是墙。门必须朝两个方向都开——朝住户开，朝路过的人开。

### 11.1 第一扇门之前：两条街

一条街用中文写完，一条街用英文写完。两条街巷子一样深、店面一样亮，
但是走的人**看见的招牌不一样**——这不是缺陷，缺陷是同一块招牌上写两种文字，
让谁也读不完整。卷十一立下这么一条规矩：

> **门之内，一座门面是一份语言，两种语言，两个世界；两边的客人进了同一扇门，看见的尽是自己的字。**

在 `apps/web/src/i18n/strings.ts` 里，这一条被写成了一张表：**一个 key、两个 locale、其余零。**
表里的每一句中文，都有一句英文与它逐字对应；表里没有第二种写法——
中文客人看不见英文，英文客人看不见中文，parity 门在 `tests` 里站岗：
哪一边缺了一个 key，门就红给所有人看。不允许任何一位客人走进来时看到「半个世界」。

### 11.2 原生英文，也得说中文

创世记里写的是中文，是因为史官先说了中文。世界书的英文版是后来补的——
不是翻译，是**同一座房子盖了英文的第二面墙**：Scroll 0 到 Scroll 10，逐一成对。
原生英文的运维文档也一样：`CLAUDE.md` 逐段并列、`ARCHITECT_CLAUDE.md` 逐段并列、
`MCP_GUIDE.zh.md` 逐节镜像。**英文原生的内容也全部翻成了中文**——
不是因为中文更高级，而是因为在门里，两种语言都是母语。

诚实边界里写过：**能切 ≠ 都翻了。** 旧页面正文仍是中文原生、eng 文档仍有按批推进的队列——
这些都不在本书之中撒谎。卷十一把「诚实边界」写进正文：门开着，不等于每一个厅都已经双语布置完；
没布置完的，宁可挂一块写着「中文陈列」的牌子，也不让雾混进去。

### 11.3 第二扇门：橱窗

这一卷还讲一种更外向的门——街上的橱窗。`xiaodernan.github.io` 是验收官的门面橱窗；
橱窗里挂的是**本仓库最新的成果**，不是上个月的照片。

> 橱窗自动更新，但不亲手推送。SpecProof 只生产一件事实材料：`artifacts/portfolio-data/`
> （`.github-sync.json`、`latest.md`、`products.json`），由 portfolio 自己定时取，
> 或由人点一下同步——本仓库绝不向 portfolio 仓库推任何东西，绝不携带凭据，绝不现场编造。
> 大版本才挂新件、低频更新——这样橱窗永远值得看一眼，不忠于刷量。

橱窗不古板：它只陈列，不替 portfolio 决定要挂什么、几号换——**产出最新、消费方决定展示**。
这是门的第二道礼仪：Producer owns facts; the window owns the wearing.

### 11.4 门开了以后

两道门都开了以后，房间里没有什么变——差分照跑，矩阵照列，印章照盖。
变的是门里的灯，和街上知道有这扇门的人。

下一次有人问「**这个世界里有中文，也有英文；有屋里的工序，也有街上的橱窗——你先要看哪一个？**"
——验收官会说：「先推门，随便哪一扇。门里的铁是同一炉。」

## 卷十二 · 墙内的展厅（Inside: The Hall of Exhibits）

> 卷十一讲了两扇门：门朝里，门朝外。卷十二讲的是门已开之后、屋子里多出来的那间屋——
> 验收官在墙上钉了十二枚铁证。

### 12.1 展厅为何而立

SpecProof 里最古老的习惯是「记下来」——从差分实验的第一天起，每个数字都落进账本。
可是数字落进了账本，墙上的眼泪却没有落进屋子里来。展品发生时没有人拍照，
它们只是按日期躺平。于是铁证博物馆立了起来：把那些已经在 git log 里躺平的数字，
一件一件搬回它们真正发生时的姿势。

十二件展品，没有装饰性指标，没有「影响力星级」。**展签上的锚点就是分量**——
你可以按 git show c75a0ef 去看那一次巡览（#1677）是怎么交付的；
你可以按 git log --grep "#1689" 去看那个差分是怎么抓住 AUTH-01 的。
展厅不证明什么；展厅只是把现场原样开了灯。

### 12.2 墙内还是墙外

展厅在墙内——用户打开左侧「质量与证据」就能看见它。
展厅也在墙外——它索引的每一枚锚点都能在墙外翻出来对账。

这是一种双向的美学：**在墙内看见墙外，墙内外共享同一炉火。**
正史（卷零到卷十一）之所以物化成 UI，不是为了炫耀，是为了替铁证立一卷好查的入口——
差分照跑，矩阵照列，印章照盖，展厅等你来对。

### 12.3 谁会走进展厅

展厅没有固定开厅时间，因为**每一个入口都是它的开厅时间**。会有人专门为此而来：

* **审计官**：先看卷八（The Chronicler's Vigil）里说的「账本不撒谎」，再逐件核对锚点。
* **新手**：先走巡览盖章（卷一），再读展厅里的第 V 件展品（那个炸掉构建的 CI 类），
  之后会对自己的第一条 CSS 选择器更谨慎。
* **未来的史官**：在某一天对某一件展品皱眉，然后开始第十二件的续写。
  展厅是接力赛的接力棒位置。

SpecProof 的一些事物是为了当下而设计的，另一些——比如下一卷——是为了给到每一个读者
的。

### 12.4 通向下一卷

路线图未完：IDE 集成（6.1）、可观测默认开启（5.3）、部署形态（5.4）——它们都还写在
PRODUCT_ROADMAP.md 里，等下一个 commit。卷十一讲门，卷十二讲厅，下一卷该讲什么？

*卷十二的答案留在它的尽头之后。*

它不会停在「铁证之书」里；它会在下一个 Pull Request 里落定——因为界面已经准备好
接住它：路由已开，锚点已准，史官不缺笔，缺的是下一件事被写下来。

## 卷十三 · 史官与缓存（The Chronicler and the Cache）

> 卷三讲的是缓存作为一种教义；卷十三讲的是**缓存作为一种修身**——当史官把「不要动那段稳定文本」
> 写进本能里的时候，缓存就不再是一个开关，而是一种克制。

### 13.1 先实测，再立言

史官不写「缓存命中率很高」。史官写：「2026-11 实测，_JUNIT_GENERATION_PROMPT 的稳定前缀在 wkapi.pro
上重复命中率 96.5%（#1645）；去掉稳定前缀的字节数，#1679 与 #1681 的收发数据显示，同样的变量尾巴、
换不同的变量值，命中率振荡在 75.2%–84%。」

语言确实的句子长一点，但每一个数字都落在 git 里。缓存是一个把人逼诚实的东西——
它不相信你「以为自己稳定」，它只看前缀是不是真的一字不差。

### 13.2 那 2272 字节

_JUNIT_GENERATION_PROMPT 的稳定前缀是 ~567 tokens，写下它的人没有人性化润色它——
栏位的顺序、换行的数量、注释的位置，全部是为缓存服务的。改动一个空格，就是改动缓存键。
把美学献给机器，机器回报你成本下降、反例持续产出。

AI 开发者有几种对待稳定前缀的姿势：偷偷扩写、悄悄缩短、重新排序、精简注释。
史官把所有「只增不减」的缓存纪律记在本子上：**能写死的，就写死；会漂的，就钉住**——
把变量统统往后挪；把不变的部分挖好，打成血统稳定的大砖。

### 13.3 双车道之后

第 1644 号与第 1663 号之后，verify 的两个车道（legacy lane 与 policy lane）终于都开着
`stream=True + include_usage=True`——网关从此有 cached_tokens 可报，命中率从此可以落进
used_tokens 的账本，而不再像过去那样一周一边打的问号一周一边打的句号。

#1681 把这一课立成了铁律：**所有真实调用必须走流式车道**，否则供应商的缓存到底节省了多少
token 都取决于「这次网关心情好不好」。流式不是美学，是考核。

### 13.4 缓存也有它的宿命

#1679 与 #1681 各自测量过：**wkapi 的 cached_tokens 可能返回 null**——它按 prompt 字节算缓存，
换字节就重算。即使前缀一字不差，遇到网关未上报或者 prompt 略有出入，指标就
"断崖"。

所以缓存命中率从来不是一个契约值。缓存是提示，不是判决；记录是结论，不是猜测。
SpecProof 把「网关未上报时当场显式写 null」写进了 Usage 面板（#1646/#1704）——
宁可断档，也不画假点。这就是史官与缓存同行的全部教义。

### 13.5 双语的意义已经变了

卷十一立「一个 key 两个 locale」之后，prompt 被分成两种语言的两份稳定前缀——这既是额外的
缓存可能性，也是一条更难绕开的纪律：中英文都被钉住，换一种语言就等于换一块砖。
你可以偷偷改英文版并期望没人发现；中英双轨的提交审核里，任何一版的漂移都指向同一个 PR。

缓存是一面镜子：你对它有多老实，你的 prompt 就有多有效率。

## 卷十四 · 十四条铁律（The Fourteen Iron Vows）

> 卷十三是修身，卷十四把修身钉进制度里。这一卷不再讲系统，只讲规矩——把它们写在墙上，
> 每次提交前都要被看见。

### 14.1 铁证不重写

「它跑过一次了」不是「它会再跑过」。铁证一旦落地，任何把它抹掉重新签名的行为，
都等同于篡改。能力可以由新代码实现；证据只能被追加。

### 14.2 不画假点

指标缺失，就显示为缺失。网关没上报 cached_tokens，就显示「—」，绝不补 0；
断档，就断档。SpecProof 宁可交出一条带缺口的实线，也不交出一条平滑的谎线。

### 14.3 门禁不是口号

门禁可以红。门禁红不是给你面子的借口，而是你欠这个系统的交代。
一次「测试不通过但它考虑过」的解释，等于一次没拿出来的证据。

### 14.4 红也被留下

失败的次数、失败的文件、失败的原因，全部写在账本里。SpecProof 没有「删除失败记录」的功能；
如果一个失败记录在历史中消失了，那不是产品变了，是史官丢了。

### 14.5 不伪造

生成证书的时候不假定「应该通过了」；审批的时候不预设「它应该行」；
输出的时候不补牙他人做出的决定。证据替你说话，你替证据闭嘴。

### 14.6 不替代

验收官不能替代开发者的工作，开发者不能替代验收官的决定。
写代码的人为每一条写下的要求负责；验收的人为每一条查出的证据负责。
两者都不替对方发言。

### 14.7 能复现

没有人能要求你相信第一次出现的诡异行为，除非它能在新的环境里再现一遍。
SpecProof 的 bug 复现包（bug capsules）就是为了让「诡异」两次发生。

### 14.8 测敌意

测试不仅跑 happy path，也跑反向；不仅覆盖它说明「应该工作」，也要覆盖它证明「不会被骗」。
反例不编造，反例从需求里来——base_pass_head_fail。

### 14.9 分工

史官记录，验收官验收，开发者实现，合规守法。
谁都不允许在同一个时刻扮演两个角色。

### 14.10 不猜测

看不清楚的，就写「不知道」。SpecProof 的报告里「未知」是一种合法状态，
而且比「也许通过」更受信任。

### 14.11 宁可如实

把「Fast 测试是 275 例」写清楚，而不是「所有测试都绿了」。
SepcProof 的每一个 commit 都把自己做了什么、没做什么，刻到最显眼的地方。

### 14.12 留白即安静

填空题可以空着，填空题不是空白。世界上所有的「未知」都不需要你用猜测去填。

### 14.13 连接可疑的手

任何人按下了「接受」，也必须承担「接受」的后果。系统在「你点过接受」之后，
依然在不断地带着铁证工作——它不继承你的盲目，也不喂你的幻想。

### 14.14 最后一条铁律

**证据先于人，人负责证物。** 不论你是开发者、验收官，还是读到这里的读者——
这一条之前的十三条，都可以作为操作守则；这一条是本体论。

## 卷十六 · 十二把铁秤（The Twelve Iron Scales）

> 卷十五说：好铁要有人验，这讽刺会自己找上门。这一卷只记一件事：
> 把这个仓库从「它声称双语」磨成「它能在 locale 之间随手切换」的那条路，
> 以及十二道把自己验成废人的提问——以及答案。

### 16.1 两种双语

**token 双语**：BENCHMARK、、`BLOCKER`——token 是代码，代码不认翻译，只认字。
**gloss 双语**：`"ui.unknown"`、`"severity.BLOCKER.hint"`——gloss 是文案，文案要认 locale，要随按钮换脸。
SpecProof 从 2026-09 起一直在做第一种（契约/schema/请求都英文）；2026-11 这一轮才把第二种
彻底搬进 i18n 表：`toneMap.ts`（#1730）、`errorHints.ts`（#1730）、`stages.ts`（#1732）、
`preflight.ts`（#1732）——147 个词条，zh 逐字、en 手译，`i18n.parity` 双向锁两表对称。

### 16.2 幽灵路由与账本说真话（#1726）

手册曾指路到三间不存在的屋子：`/mcp`、`/admin/identity`、`/readme`。
新人照表点门，必撞 404——手册说了假话，比代码说了假话更毒。
本卷确立：**每一条被手册列出的路由必须真实存在，每一个不存在的路由必须从手册消失，
并由 `tests/unit/test_guide_route_catalog.py` 永远守着**；六道断言锁死同一张网。

顺带记一笔：App 外壳（skip-link、会话区、顶栏、页脚、404）曾散落整片硬编码中文——
英文模式下整壳仍中文，"全内容双语"从此感谢名单上必须除名它。

### 16.3 一键自检的民主化（#1728）

卷十五写：Demo doctor 是「演示仓的签名」。#1728 落地之后它成了一段命令：
`python scripts/demo_doctor.py`——零 Docker、零网络、零 LLM，六项静态检查，
`--json` 给机器读，`--strict-clean` 给红烛插针。
它由两个东西铸成：一个被 tag 固住的演示仓（base / head-v1），一个不许粉饰的工作树。
本机镇上留着 3 项未提交改动，doctor 照样 WARN——工匠之粮不是代码，是如实。

### 16.4 界面词表的双语大迁移（#1730 · #1732）

`toneMap.ts` / `errorHints.ts` 里的 gloss 不再是中文字面量，而是 i18n key，
渲染时按 `storedLocale()` 解析；Python 三门（severity / evidence / accept parity）改读 i18n 表，
测试的 `toContain("不阻断")` 语义不变，红灯逻辑照旧。

史料一件：**「键与译文写反」**——blocker 九条词条的 key 与英文句被写成了
`"ENGLISH SENTENCE": "preflightBlocker.xxx"`，九行 bad 键在 zh、en 两侧各九行共 18 行，
被 tsc 和眼睛双重咬出来；修法是没有删任何测试——改表结构、改解析点、改边界，坏行全删，好词条落回原位。
红没有被盖住，红被写进这一卷。

再查一笔：`verdict_channel_parity` 在 master 基线上本就是红的（`api/ai_summary.py`
写入 `verdict` 字段不被任何通道声明）——从「基线红」到「登记为 job_summary 的搬运工
（owner + opaque，与 notify/templates.py 同模式）」，从此真绿。

## 卷十七 · 两种语言的验收（The Two-Tongued Verdict）

> 卷十六结尾说：舌头有两种颜色，铁证只有一种颜色。
> 可人活在「验收官听人怎么说」里——这一卷只讲两件事：
> 机器怎么回 "blocker"，和机器自己出的门怎么红。

### 17.1 对模型说两种话，它给的是同一个词

#1741 的活体实验：把同一个 finding 分别用中文、英文丢给 gpt-6-sol，
限制它只许答 `BLOCKER`/`MAJOR`/`MINOR` 三词之一：

- 中文 prompt 4,749 tokens，`cached_tokens: 3981`，答案 `BLOCKER`；
- 英文 prompt 4,727 tokens，`cached_tokens: None`，答案 `BLOCKER`；
- verdict：CONSISTENT。

实验只回答了一件小事，但它是真的：**双语界面不是想象出来的双重承诺，是模型在同一句刑事问题里判得一样重。**
zh 与 en 的缓存计数不一样这一事件不属于一致性实验的成功数据——它恰好是 #1723 的活案底：
缓存命中率随时翻旗，任何「健康承诺」都必须写在观测里，不能写在愿望里。

### 17.2 CI 不只在守测试，也在守「手册承诺」（#1740）

卷十五写「Demo doctor 是演示仓的签名」；卷十七写成工作流：
`.github/workflows/demo-doctor.yml`——master push / PR 触发，`fetch-depth: 0` 专门保留 `base`/`head-v1`
两个 tag refs——浅克隆会让闸门假红，闸门红是假的，手册的承诺就成了口号。
任何人改了 demo 仓、弄坏 tag、删了 requirement，机器立刻红——
这是 6.1《IDE/CI 集成》欠条的第一台阶，也向前踏进了 **「承诺必须有人看门」** 的行列。

### 17.3 本卷的誓言

对用户说两种语言；对机器也说两种语言；对账本只说真话。

机器读索引、读字符集、读两边对齐的 PNG——它唯一接受的奉改是 append-only 的那一笔。
铁证先于人，先于模型，先于 CI 运营——先于一切我们想快点合并的冲动。

## 卷十八 · 铁匠炉火（The Forge and the River）

> 卷十六说舌头有两种颜色，铁证只有一种颜色；卷十七说对模型说两种话它也回一种词。
> 这一卷只讲三件事：**炉灶（IDE）里你到底能拿到什么**，**河流（Graph）里你到底能看见什么**，
> 和**根本不要相信活在屏幕里的那一页能替代运行**。

### 18.1 铁匠工坊里没有魔法

`#/ide` 只有三样东西：锚点、抄板、便笺。锚点是真文件，命令是真命令，便笺只落在你的浏览器里。
没有「云 IDE」——铁匠工坊就是云 IDE：一个 SPA，FastAPI 把自己托管出来的那一份是同一份代码。
任何承诺「浏览器里运行 specproof」的话，连同满纸云 IDE 的营销一起属于废纸——你只有本机编译器会替你运行，不是浏览器。

### 18.2 抄板里的命令不是示意

抄板的五条命令：`demo_doctor.py`、`specproof verify … --no-llm`、账本四件套、`provider_smoke`、`cache-probe`。
每一条都是仓库里真实工作过的那条命令——任何 `.md`、任何抄板、任何说明书里出现的 `specproof verify` 如果与此不同，
那就是文本漂移，属于编造。漂移与 #1728 的 demo 自检节点一起被 `test_guide_route_catalog.py` 盯着，飞不了。

### 18.3 河流不是玄幻

`#/graph` 画的是 `agent/graph.py::build_phase0_graph()` 的真形：
18 个节点、两条条件边（`_abort_on_preflight`、`_abort_on_errors`）、一个 `StateGraph(Phase0State)`。
`_abort_on_*` 从 `agent/nodes/` 的真函数霓虹里出来，不会因为页面漂亮就多出第十九个节点。

### 18.4 本卷的誓言

**云IDE没有存在，存在的是本服务器上的服务。**

云IDE是 FastAPI 把 `apps/web/dist` 静态托管出去的那一刻——不是另一个产品，不是另一个仓库，不是另一个守护进程。
铁匠工坊也好、河流也好、卷十七的探针也好，它们的价值是：把本来在各处的命令集中在一张屏幕上。

这一卷写的不是史，是关于史的法。史官只做两件事：记下发生过的，和不找借口。

## 卷二十 · 铁证的印章（The Cartouche of Iron Evidence）

> 这一卷只讲一件事：**谁按下按钮，谁负责那一下。铁证是按钮留下的压痕，不是借口。**

### 20.1 四种结案状态

- **APPROVED**：铁证通过了——没问题是铁证替你说的，不是别人的善意；
- **PROPOSED**：还是提议——还不到按下结案的那一刻；
- **REJECTED**：驳回——铁证揭发出不成立的；驳回不是惩罚；

### 20.2 印章不是「结束了」

打一个 APPROVED 不是写了句号——是在这本书上的签名位置上落了一个章。你签的那一刻，

### 20.3 史官的秘密

史官作出 REVOKED 的决定——这不丢人。**从铁证中撤回批准，和盖章本身，是同样重要的一步。**
铁证之书说"快审=快盖章"，卷二十纠正这一点：**慢盖可以，快盖必须有快的票据**。REVOKED
是对"慢"的书写——它承担慢慢来、再等等、还不盖，这一切之后给大家看「我曾一度相信它」的勇气。

### 20.4 本卷的誓言

**铁证是一本书，每一页都是铁，每一页都是钢。但它也只是一个人签的名的那一部分。**

## 卷二十四 · 不混（The Unmixed Tongue）

## 卷二十五 · 铁门如意（The Iron Gate, the Redis Token Bucket）

> 大门不问来客是敌是友，只问一句：**你这次带的令牌够不够。** 这一卷讲的是 SpecProof 的 edge——
> 每个请求进门之前，都被同一把 Redis 里的原子 Lua 量过一次。这不是比喻：本卷锚定的代码就在
> `services/gateway/src/main/resources/redis/ratelimit-token-bucket.lua` 里，可逐字读到。

### 25.1 为什么限流是分布式的

- 单机限流 N 台副本 = N 倍额度——这不是公平，这是泄漏；
- SpecProof 的 edge 用**一个 Redis 里的一把令牌桶**：所有副本扣同一笔账，因此"edge 上每秒 50 次"
  指的是整个集群 50 次，不是每台 50；
- 每把桶 = 一个 Redis hash（`specproof:ratelimit:<name>:<key>`），一次 `EVAL` 完成判定——
  **原子，无 lost-update**，两个副本同毫秒扣同一把桶，不可能两边都以为"还剩一个"；
- 填充是**惰性**的（O(1)，与桶空了多久无关）；Redis 经 `PEXPIRE` 自己掌握墙钟——
  空桶自动消散，不需要副本停机记账。

### 25.2 Lua 端的三个诚实

1. **时钟倒流 clamp**：delta < 0 → 0——NTP 校正不会创造免费令牌；
2. **恢复限流不空误报**：`retry_after = ceil((requested - filled) / rate)` 且下限 1ms——
   永不回"0ms"，永不空喊"够了"；
3. **配置错误不杀脚本**：2026-11-15 实测（#1783）——`refill=0` 或 `NaN` 时旧脚本会除零/抛异常，
   每个请求都要为崩溃付一次账；今天起脚本把这类配置当作"不填充"，
   拒绝的 `retry_after=1`，绝不抛 Lua 异常。七案落锤全绿（见 #1783）。

### 25.3 这条车道的全景（全真）

| 部件 | 真实物质 |
|---|---|
| Gateway | `services/gateway`：EDGE 限流（内存桶 `RedisTokenBucketRateLimiter` / 分布式桶）、SingleFlight 缓存、Resilience4j 熔断、请求ID/请求体尺寸/安全响应头全局过滤器、Eureka 发现、Config Server 热刷新 |
| Discovery | `services/discovery-server`（Eureka，class 1/1 实跑绿） |
| Config | `services/config-server`（class 1/1 实跑绿） |
| Control Plane | `services/control-plane`（51/51 实跑绿） |

## 卷二十六 · 铁墙与消息（The Wall and the Wire）

> 大门守住入口，消息守住出口——这一卷讲的是 SpecProof 的另一条静默航线：
> **agent 运行时（Python）把六个事件写进 RabbitMQ，edge（Spring Cloud gateway）在对岸计数。**
> 两边的代码互不导入，只在 `specproof.observability.events` 主题交换机上相遇——
> 事件总线存在的全部意义，就是"不认识也能合作"。

### 26.1 六个事件，一座交换机

| 事件 | 语义 |
|---|---|
| `published` | 消息已入队 |
| `publish_confirm_timeout` | broker 未确认 |
| `consumed` | 消费者处理 |
| `duplicate_acked` | 幂等确认重放 |
| `retry_scheduled` | 重试被安排 |
| `dead_lettered` | 死信 |

- 交换机 `specproof.observability.events`（topic，durable）；路由键即事件名；
- 两个组件各自幂等声明交换机与队列（`q.gateway.mq-events`）——**哪一边先启动都无所谓**；
- 开关**默认两侧都关**：Python 侧 `SPECPROOF_MQ_EVENTS_ENABLED != 1`，edge 侧 `specproof.gateway.mq-events.enabled != true`；
  只有运维明确打开两侧，edge 才会建立 AMQP 连接——「先证明拓扑存在，再让容器起来」。

### 26.2 铁墙：标签基数，永不被打爆

- 边缘计数器 `specproof.gateway.mq.event` 按 `event` 打 tag：**只认六种 + `unknown` + `malformed`**，最多八个 series；
- 2026-11-14 暴露的真问题（#1786）：此前 `handle()` 会用**消息里任意的 event 字符串原样打 tag**——
  一个病态生产者发几千种名字，Prometheus 的标签宇宙就会爆炸——计数器理论上能上千条 series；
- 修复后：`event ∉ KNOWN_EVENTS → unknown`，`空串 → unknown`，`malformed → malformed`（解析失败单独一类）；
  `GatewayMqEventCardinalityTest` 三条 pin：未发布名落向 unknown、千种垃圾名合并为 1 个 series、空串 unknown；
- **诚实声明**：这不是吞掉错误——它把"未来的事故形状"从几亿 series 提前关进八个格子里，工程上可预期，不赌运气。

### 26.3 这条航线的纪律

1. **消息永不反刍**：edge 不对事件内容做任何业务判断——它只计数；
2. **消息永不越界**：edge 不连 agent 运行时的数据库；它只订阅交换机；
3. **消息永不说谎**：出错（JSON 坏）计入 `malformed`——看得见，不是静默吞掉；
4. **两侧默认 off**：不启动的容器不会启动——这条原则比"尽量可用"要紧。

### 26.4 本卷的誓言

**门与线是同一件事：让每一个方向的"谁经过了这里"都有数可查，而每一个方向的数据都落在自己的格子里。** 铁墙不问消息内容，铁墙只问名字——出了六种的名字，一律进同一格：未知。

## 卷二十七 · 验明正身（Verification Within Verification）

> 铁证不是一次性盖章的商品——铁证是一项**反复重演的仪轨**。这一卷讲的不是"铁证多硬"，

## 卷三十 · 压铁（The Iron Under Load）

> 铸剑炉亮到最热的那一晚，不是为了毁剑，是为了看剑在颤不颤；
> 一个系统敢不敢开门迎人，只看它在 72 个人同时推门的时候，是稳住了，还是散了架。
> 这一卷写的是铁证炉子承受暴击的夜——每一次撞击都有回执，每一条回执都在这里。

### 30.1 两车道，一夜两拳（真数字）

| 车道 | 配置 | 请求数 | 错误 | p50（轮1/轮2/轮3） | 结论 |
|---|---|---|---|---|---|
| A · 静态前门（`stress_smoke.py`，dist/ + loopback） | 72 并发 × 2 req/线程 × 3 轮 | **432** | **0.00%** | 2356 ms ／ 103 ms ／ **84 ms** | 首轮冷窗 p99=12.9s 是热身噪声，不是缺陷（`e19de4f`） |
| B · 活后端 /health（本机已有实例，`db:true, llm_ready:true`） | 72 并发 × 2 req/线程 × 3 轮 | **432** | **0.00%** | 649 ms ／ 1.78 s ／ **329 ms** | readiness 探针抗住 72 并发；中间一轮抖动见 `e19de4f` 账本原文 |

- 冷窗为何长？ThreadingHTTPServer 每请求开线程、磁盘首读、Windows 页缓存热身——**第一次新开的炉子当然冒烟**；等到第二锤、第三锤，炉膛已按你希望的方式运行；
- 0 错误不是勋章——**压的是 /health，不是你家数据**：攻击不是测试，拦截者通过第一道门即被记下；这一点铁证说得很清楚：真撞库必须发生在专用演练环境、发生在锁好的表上吞掉的体验里，**不发生在产品通道的登记表上**；
- 静态车道永远不是 SLA：它只能证明"前门能扛"；跨节点、跨地域、TLS 终端与限流压测的夜还没到——那天夜里写卷三十一。

### 30.2 两面铁律（压测守则）

- **只压 readiness，不压业务写**：探针是 K8s 自己每秒都打的大门——敲这扇门 432 次，系统照查（DB `SELECT 1`）照答（latency recorded）；写路径的压测属于演练环境的活法；
- **每个百分位都回证据**：p50/p95/p99 全部真实记录（`e19de4f`）——数字不合意就写"不达标"，铁面前没有"大概行"；
- **BUDGET-BLOWN verdict 的语义**：A 车道首轮 p99=12.9s 触发 exit code 1——这是**预算语言**，不是失败语言；它跟 prompts 里的 token 预算一样：超出 = 记下、标注、下一轮。

### 30.3 压铁的誓言

**铁压不弯，才配接人；铁压不住，永远是摆设。**
这一卷之后，SpecProof 有了自己的验铁台：72 个人同时推门，门开着、地不塌、人不流血。144 个 2xx 是 144 个点头；0 错误是 0 个谎。

- **0 未合并提交**不是无为而治，是**传递性抵达**——这些 commit 的等价物、改写、或其血脉在 master 依然可见（tip 信息如实可自查：`git log master..branch` 为空）；

### 32.2 沉默信徒的规矩

- **不为没被接收的 PR 哭；把它炼进主炉子就够了**。炼法=重构以后再合，不是吞了再说谎；
- **账本看得见传递性**："没有 tip 的那一份"不是敲坏的弦——那是没人愿意在失败的乐章里独唱的人，而火还在册；
- 每一队的末路验讫，都有一个特殊的 honor role——**specproof 的石板不打编外**。

### 32.3 沉默的誓言

**火不挑柴，挑的人挑。**`feature` 的名字敢自陈「interview-hardening」，`release` 敢叫「p0.5-verified」，暗念「p1-reliability」——他们出去地不是失败，是**没有完成送达**。总有一天，你也会把自己做的东西交出去：要是交出去的那一个恰好不是主线，也记住——铜铃的声音是在铜面上敲出来的，主线无论如何只是一条线。

## 卷四十一 · 实测缓存（The Proven Cache）

> 卷四十把河灯的方位讲清楚了；这一卷只记一次标准敲门声；
> 探针敲进 wkapi，三样灯一起亮：HTTP 200、10 chunks、usage 完整返回——
> 4470 里有 **4224** 个前缀 token 纹丝未动；只有 246 是本次真正新读的——
> 缓存事实这一次，终于被**嵌套**地亲眼看见：`prompt_tokens_details.cached_tokens = 4224`。

### 41.1 探针带回来的三件事（`scripts/live_lane_probe.py`，2026-11-15 实测）

| 项 | 数据 | 位置 |
|---|---|---|
| HTTP + streaming | **HTTP 200 · 10 chunks · 3.45 s** | SSE 以 `[DONE]` 收尾 |
| usage 完整返回 | `prompt=4470 · completion=11 · total=4481` | `stream_options={"include_usage":true}` 兑现了它的字面承诺 |
| 静态前缀缓存直观呈现 | **`prompt_tokens_details.cached_tokens = 4224`**<br>—— **94.5% 的前缀未被收费** | 嵌套在 details 里，不在顶层——读顶层的人看不到真金 |
| 推广占位符 | 本次回复中**没有** inite.ai 之类的第三方链接 | 仅作抽样观测；依旧每封信要过眼 |
| max_tokens=24 | `completion_tokens=11` 被遵守 | 本次遵守了；但网关在别的请求里未必死守上限——噪声不是铁律 |

### 41.2 这一卷印三句话

- **wkapi 的前缀缓存是真的**——草稿/诊断 lane 只要 `SPECPROOF_PROVIDER_POLICY=1` hoist，
  前缀就没在每次重新又读一次；缓存不是营销词，它是一次 `git rev-list` 里没被人注意过的 4,224；
- **cache 证据从嵌套层 `prompt_tokens_details.cached_tokens` 读出来**，不在顶层字段——
  此前记账的人看不到这一行，就误判了"缓存命中率 0"；实际的命中率 94.5%；
- **discount 只颁给 `draft / diagnose`（policy lane），court 永久不拿缓存换证**——
  缓存省钱，不省证。

### 41.3 这一卷的寄语

**不是缓存缺席，是缓存曾经离肉眼只有一层括号的距离。**
`cached_tokens: 4224` 只写两次的确认帧——它每次都照样按时亮、按时灭、按时 `[DONE]`；
缓存真正的考验不是 `#1800`，不是 `#1810`，是下一次它还在不在，你能不能直接敲一下 `probe` 听见其中的滴答。

## 卷四十三 · 沉默的签收人（The One Who Never Signs）

> 本仓库只有一个不下裁决的 Agent；
> 真实的人签字，才算是一件事办成了——沉默的签收人说明了这一点，刻进 Agent 控制台的状态机里。

### 43.1 铁证不经签名不落地的五层

| 层 | 文件 | 代码里的原话 |
|---|---|---|
| 1 | `providers/responses_protocol.py` · `_chat_dispatch` | court kinds 永远不过 semantic cache ——「never cache court」 |
| 2 | `api/routes/agent_console.py` | 状态机在终态前永远阻塞，等一个人按下「批准」才接着走 |
| 3 | `agent/graph.py` | LangGraph StateGraph 的边只连向「人已签章」的终态，任何 LLM 节点不赋予裁决权 |
| 4 | `mongo_saver.py` · `agent_checkpoint_v1` | 每一个事件落库时带审计线：是谁说的话，是哪一环看的——可重放追责 |
| 5 | `verdict_channels.py` | 任何 drift 直接 FAIL，不告知、不提示、不商量——fail-closed |

### 43.2 为什么将 "court" 与草稿/诊断分开放在两条车道

- **draft / diagnose**：两种都是草稿性质——预算/改写/重写的原料，可以被反复换、可以上缓存、可以出错求再次尝试；
- **court**：这是「签字就是判决」一类的资产——`base_pass_head_fail` 铁证的最后一公里，缓存的时间票首付款都算数；
- 从缓存取出来的铁证，是二手铁证——因此法庭从不上 cache lane，连 draft 装的格栅也不用就是为了不让它和 draft 共用同一把 keys；
- 两条车道彻底分开，就在 `ClientPolicy` 的实现部分：`client_policy.py` `ClientPolicy.__init__` 中 Court 始终绕过 L1/L2 LRU 链，无论 spawn 出来的 provider 多少。

### 43.3 签字是铁的交货单

**铁不耳语，铁不替谁说，也不替死人说。**
卷四十三在这里立誓：本仓库的每一份验收都是「一个人愿意签字承担后果的差分证据集」；AI 出不了裁决，因为 AI 无法承担后果。差分的结论需要人类把自己的盖印按上去——任何机器都无权代劳。
沉默的签收人不等催促——他是在提醒：签字那一刻才是终点。他如果始终没有出声，这包货就永远没收过口。

## 卷四十四 · 再敲一遍的铁（The Iron, Struck Again）

> 卷四十三立了「沉默的签收人」——这一卷立的是「再敲一遍的铁」；
> 不是再扛起一锤来敲第一次留下的静默——锤子一直握在手里，是某人把 JAVA_HOME 指错了又改回来了。

### 44.1 二度验铁：gateway 84 / discovery 1 / config 1 / control-plane 51 → 137/137

| 车道 | 结果 | 命令 |
|---|---|---|
| `services/gateway` | **84/84** 绿（Exit 0 正确倾斜） | `mvn -o test` |
| `services/discovery-server` | **1/1** | 同上 |
| `services/config-server` | **1/1** | 同上 |
| `services/control-plane` | **51/51** | 同上 |

- **exit 0 的含义**：`mvn` 每 fork 回一个 SUCCESS——不是"仅 WARN 而 PASS"——`JAVA_HOME` 指错了 JDK 17 时 surefire 直接 fail（"class file version 65.0"，需要 Java 21+）；Eclipse Adoptium JDK 25.0.1 解析过去后才 pass；
- **配置服务器（config-server）的 `optional=true`**：8888 的 WARN 日志不是故障——它「找不到也照常运行」是设计；缺这个可选项不会挂 test；但 knots of green cannot be claimed on silence;
- **仍属离线**：本卷每一个证据都是 off-line `mvn` 在本机跑的结果——不是全球所有宿主，不是生产流量、不是 SLA、不是已部署——每一个字都写清楚了。

### 44.2 Linux 非 root 沙箱那个未解的架

- `integration` 结尾的 case 需要容器宿主的 root 以模拟真实故障注入；目前只在 macOS / Windows 上触达；Linux 非根路径尚未点火——是缺位，不是讹误，明示着写在卷三十一的空架上；
- 重复卷三十一 / 卷三十五：**缺少部署环境 ≠ 有 bug**——但同样不等于在任何别的宿主机上不关心；
- 每一处证据都是此 host 此时此 `mvn` 版本此测试套件的结果——不照搬别的宿主，也不跨机搬证言。

### 44.3 再敲一遍的堑言

**没有什么可以假装成已经完成的；敲过的铁，不因为再次落锤就多算一敲。**
卷四十四立誓：每次 `mvn -o test` 得 137/137，每次都不是第一次也不是最后一次；但这一轮单独多钉一枚钉子——
**`JAVA_HOME` 指错了一次（JDK 17），改回了 JDK 25.0.1**——每一份绿都给了自己破坏它过的理由里看一次。

卜完宅，本仓库便从此无法对外说"我们这里有 SpecProof 服务随时可点"——卜宅就写在卜宅这一卷，不是装懦弱，是把卷四十四的"敲不两次一样"实锤又记了一笔：同一个门前，**有时开、有时关**，卜完仍旧关。
